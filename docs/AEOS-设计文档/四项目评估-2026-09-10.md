# 四个候选项目评估 · 能否补全一体化？

> **评估日期**：2026-09-10 ｜ **对象**：qihang-oms / AionUi / NocoBase / CRMEB
> **方式**：GitHub API 实测（星级、许可、技术栈）+ 许可证原文解码 + 与项目已有能力对照
> **结论先说**：**能补的只有两块，其中一块被许可证挡死；真正值得引的只有一个。**

## 一、四个项目档案（实测）

| 项目 | 星标 | 技术栈 | 许可证 | 与本项目栈匹配度 |
|---|---:|---|---|---|
| **AionUi** | **32,718** | TypeScript | **Apache-2.0** ✅ | 高（前端同栈） |
| **NocoBase** | 24,123 | TypeScript | Apache-2.0 **+ 附加条款** 🚫 | 中 |
| **CRMEB** | 9,320 | **PHP / ThinkPHP6** + Vue | Apache-2.0 ⚠️ | **低（异栈）** |
| **qihang-oms** | **28** | **Java / SpringBoot3** | **AGPL-3.0** 🚫 | **低（异栈）** |

**定位：**

- **AionUi** —— 开源 24/7 **Cowork 应用**，统一驱动 OpenClaw / Hermes / Claude Code / Codex / OpenCode 等 **20+ CLI Agent**，可自定义助手、组队协作。
- **NocoBase** —— AI + 无代码业务系统平台（CRM/ERP/低代码/工作流），卖点是「AI 在成熟基础设施上生成，而非从零生成」。
- **CRMEB** —— 多语言**商城系统**（小程序/H5/公众号/PC/App），含分销、拼团、砍价、秒杀、优惠券、积分、会员等级、直播、页面 DIY。
- **qihang-oms** —— 电商**订单中台**（淘宝/京东/拼多多/抖店/微信小店），商品/订单/售后/发货 + 电子面单，可对接 ERP/WMS/财务。

## 二、🚫 许可证是硬门槛 —— 两个直接出局

这个项目对许可证有明确纪律（`AGENTS.md`：GoodJob `whatsapp-plugin` GPL-3.0 **永不入树**；TradeAI MIT 无 LICENSE 需书面确认）。按同一把尺子量：

### NocoBase：条款 5.4 明确禁止做 SaaS ☠️

我解码了它的 `LICENSE.txt`（Apache-2.0 + 附加条款），关键一条：

> **5.4 不得向公众提供任何形式的无代码 / 零代码 / 低代码 / AI 平台 SaaS/PaaS 产品（基于原始或修改的软件）**

**而优丁正是一个多租户 SaaS 平台。** 条款 7.4 再次重申。**结论：NocoBase 不能用**——用了就违约。

### qihang-oms：AGPL-3.0 网络 copyleft ☠️

AGPL 比 GPL 更严：**通过网络提供服务即触发源码开放义务**。对一个对外收费的 SaaS 来说，这意味着要把衍生源码开放给所有使用者。**结论：不能进主仓。**

### CRMEB：标注 Apache-2.0，但需核实 ⚠️

CRMEB 官方有「免费版 / 商业授权」双轨，GitHub 上标 Apache-2.0，但**商用条款需以官方授权说明为准**。引入前必须核实。

### AionUi：Apache-2.0 ✅

干净，可用。

## 三、对照你的愿景链：哪些真的补了洞？

你的目标链：`上传图片→AI建站 → 发新闻/产品 → 生产视频 → 多平台分发 → 自动规则 → 互动回流获客 → 论坛发帖获客 → 各渠道获客 → SEO/GEO/AAO → 开发信/背调 → 客户跟踪 → 订单发货 → 物流跟踪`

**先说个反直觉的事实：这条链项目里已经有 70% 了。**

| 环节 | 项目现状 | 四个候选能补？ |
|---|---|---|
| AI 建站 | ✅ `ai_site_engine` + `site_builder`（真） | — |
| 内容/新闻/产品 | ✅ `content_master`（真，表空） | — |
| 生产视频 | ✅ `video_publish_orchestrator` + `media_factory` | — |
| 多平台分发 | ✅ `unified_publish` + n8n | — |
| SEO / GEO | ✅ `seo_matrix` + `geo_engine` | — |
| 开发信 / 背调 | ✅ `outreach` + `prospect_research` + `trade_intel` | — |
| 客户跟踪 | ✅ `crm_pipeline` + `opportunity` | — |
| 物流跟踪 | ✅ `logistics/track` | — |
| **外层编排（拆解需求）** | 🔴 **死代码**（`harness_gateway` 是桩） | ✅ **AionUi 正好补这里** |
| **订单（贸易）** | 🔴 **无路由** | 🟡 qihang-oms 可参照（但 AGPL 不能引） |
| **商城交易玩法** | ❌ **完全没有**（无拼团/砍价/秒杀/分销） | 🟡 CRMEB 有（但 PHP 异栈） |
| **论坛获客** | ⚠️ 部分 | — |

### 真正被补上的洞只有一个半

1. **AionUi → 外层 Harness**（🔴 真洞）：我上一轮查出 `harness_gateway.py` 是死代码、任务图来自硬编码模板。**AionUi 是一个现成的「统一驱动多 CLI Agent」的 Cowork 层**，而且它已支持 OpenClaw / Hermes —— 正好是项目在用的。**这是四个里唯一值得引的。**

2. **CRMEB → 商城交易玩法**（❌ 真空白）：项目完全没有拼团/砍价/秒杀/分销/优惠券这些。但 **CRMEB 是 PHP/ThinkPHP6**，引进来等于多养一套后端 + 多一套数据库。**建议只抄玩法模型，不引代码。**

3. **qihang-oms → 订单中台**：项目确实缺贸易订单路由，但 **AGPL 不能引**，且只有 28 星、Java 栈。**最多作为「订单状态设计」的参考。**

4. **NocoBase**：能力上（低代码搭业务系统）与项目已有的 318 视图 admin **重叠**，且许可禁止 SaaS。**不建议。**

## 四、⚠️ 一个必须说的结构性问题

**项目现在已经有 12 个编排引擎**（UBrain / Hermes / Paperclip / DeerFlow / Evolution / Wangcai / agent_loop / pipeline / orchestrator / video_publish / workflow_canvas / growth_loop），`AGENTS.md` §4 自己就警告过「**本仓库能力极重叠，极易重复造轮子**」。

**在这个基础上再引入 4 个完整系统，不会变成「一体化」，只会变成 16 个系统互相打架。**

而且两个是**异栈**（PHP / Java）——引入后你要同时维护 Python + Node + PHP + Java 四套后端。

## 五、建议

| 项目 | 建议 | 理由 |
|---|---|---|
| **AionUi** | ✅ **引入** | 唯一补上真洞（外层编排），Apache-2.0，同栈 |
| **CRMEB** | 🟡 **只取玩法** | 抄分销/拼团/砍价/秒杀的**模型设计**，不引 PHP 代码 |
| **NocoBase** | 🚫 **不引** | 许可 5.4 禁止做 SaaS；能力与现有 admin 重叠 |
| **qihang-oms** | 🚫 **不引** | AGPL-3.0 网络 copyleft；28★；Java 异栈 |

**一句话**：这四个补不齐「一体化」。你缺的不是更多系统，是**把已有的 12 个收敛成 1 个**——这正是我上一轮说的那个收敛工作。AionUi 值得引，是因为它**替你把「外层编排」那个死掉的入口变成了真的**，而不是又一个平行系统。
