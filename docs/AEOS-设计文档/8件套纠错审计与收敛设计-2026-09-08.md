## 二、收敛设计 · 统一的真相源模型（核心方案）

### 2.1 两个"真相源"分层，不再混用

```
┌─ 开发真相源（代码演进发生地）──────────────────────┐
│ 上线网站.worktrees/…/ = git 工作树，后端+前端持续开发   │
│ 官网 = frontend/（Nuxt3 开发版）                      │
└────────────────────────────────────────────────────┘
              │  发布 / 迁移 / 同步（build→copy→run）
              ▼
┌─ 运行真相源（3000 对外实际跑的版本）─────────────────┐
│ 主要备份/上线网站/frontend = Vite 化运行版            │
│ （main.ts+index.html；暖米白 #f5f4f0 / 砖橙；Nuxt 兼容垫片）│
└────────────────────────────────────────────────────┘
```

关键洞察：**`主要备份/上线网站/frontend` 不是"旧存档"，而是 worktree 前端的"无 Nuxt 可运行化"镜像**，当前被 09-07 运维索引选为 3000 运行源。因此：
- 谈**代码结构/组件/API** → 以 worktree（含 Nuxt 与最新组件）为准。
- 谈**端口 3000 / 对外官网/主题色/启动** → 以"运行真相源"为准，且其 git 无提交 = 运行副本，改前先回同步源。

### 2.2 建议的收敛路径（消除双版本，供选择）

| 方案 | 做法 | 代价 | 适用 |
|------|------|------|------|
| **A（推荐）确立"双形态、单一运行源"** | worktree Nuxt 开发 → 构建产物/源码同步进 `主要备份 frontend` Vite 运行源；文档把两者写成同一产品前端的"开发版/运行版" | 需维护同步脚本 | 当前迁移中间态最稳妥 |
| **B 二选一收敛到 Vite** | 正式废弃 Nuxt 官网，前端统一为 Vite 运行版结构，worktree frontend 仅作归档 | 一次较大重构/迁移 | 若确认不再回 Nuxt |
| **C 二选一收敛到 Nuxt** | 撤掉 3000 的 Vite 运行版，回到 worktree Nuxt | 推翻 09-07 决策 | 若确认 09-07 索引是临时 |

> 本设计不擅自替你选 B/C；**默认按 A** 编写文档（最不撒谎、最可维护），把 B/C 作为显式"待决决策"记录，待你拍板后再收敛。

## 三、文档架构设计（如何让 8 件套在双版本下不漂移）

1. **加一处"版本状态说明"入口**：建议在 `AGENTS.md` 增一节「当前版本状态」，用一个表格明示：开发真相源 / 运行真相源 / 官网主色 / 待决决策（链接 README 口径提醒）。未来任何一方变化，只改这一节 + README 提示，不必翻全文。
2. **口径分级**：
   - 稳定事实（后端架构/角色/模块/命令）→ 写死。
   - 易变口径（官网技术栈/主色/端口运行态）→ 一律加「运行态以最新运维索引为准」前缀，不写死。
3. **DESIGN 主色改为"分层真源"**：平台品牌/后台=薄荷；官网对外主题=按其运行版主色（暖米白底+砖橙 CTA），并标"若收敛到单一前端，主色统一为该前端令牌"。这样无论最后选哪套，DESIGN 都不错。
