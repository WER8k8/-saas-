四、场景生成逻辑说明

4.1 编号规则

场景编号 = SC-{人格ID}-{行业编号}-{流程编号}
示例：SC-A01-IND01-STG01 = 张小白（外贸零基础）在建材行业进行开户引导操作

4.2 优先级判定

P0 核心场景（~2,000）：新手人格(A) × 核心流程(STG-01~06) + 老手人格(B) × 全流程 + 所有性格极端型(C) × 核心流程
P1 重要场景（~4,000）：业务规模型(D) × 全流程 + 使用场景型(E) × 全流程 + 触发事件型(F) × 全流程
P2 一般场景（~4,000）：情绪型(G) × 全流程 + 特殊需求型(H) × 全流程 + 安全攻防(I) + 专家审计(J)

4.3 场景描述生成规则

每个场景描述由以下要素组合生成：
人格特质 → 决定操作风格和期望
② 行业背景 → 决定产品数据和业务术语
③ 流程阶段 → 决定操作路径和功能模块
④ 情境变量 → 决定时间压力/设备/网络/数据量
⑤ 预期行为 → 该人格在此情境下会做什么
⑥ 潜在问题 → 可能遇到的困难或异常

4.4 测试执行建议

批次 1（P0 核心，~2,000 场景）：新手 + 老手 × 7 步闭环 → 验证核心业务可用性
批次 2（P0 边界，~500 场景）：性格极端型 × 核心流程 → 验证异常处理
批次 3（P1 业务，~4,000 场景）：规模型 + 场景型 + 事件型 × 全流程 → 验证业务适配性
批次 4（P2 长尾，~3,500 场景）：情绪型 + 特殊需求 × 全流程 → 验证体验一致性
批次 5（安全+审计，~500 场景）：攻防型 + 专家型 → 验证安全与架构
