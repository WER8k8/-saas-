## 二、最关键的发现：它靠 ACP 接 Agent

**AionUi 与外部 CLI Agent 的通信协议是 ACP（Agent Client Protocol）**，由 `@agentclientprotocol/sdk` 提供。

**接入的确切格式**（`examples/hello-world-extension/contributes/acp-adapters.json`）：

```json
[
  { "id": "...", "name": "...",
    "connectionType": "stdio",          // spawn 本地 CLI
    "cliCommand": "echo", "acpArgs": ["--acp"],
    "healthCheck": { "versionCommand": "echo 1.0.0", "timeout": 3000 },
    "models": [...] },

  { "id": "...", "name": "...",
    "connectionType": "http",           // 连远端端点
    "endpoint": "http://localhost:8080/acp",
    "apiKeyFields": [{ "key": "HELLO_API_KEY", "type": "password", "required": true }] }
]
```

**两种传输**：`stdio`（本地子进程）｜`http`（远端端点，带 API Key 鉴权）。

**执行引擎类型**（`detectedAgent.ts`）：
```
DetectedAgentKind   = 'acp' | 'remote' | 'aionrs' | 'openclaw-gateway' | 'nanobot'
RemoteAgentProtocol = 'openclaw' | 'zeroclaw' | 'acp'
```
→ **`openclaw` 确实在列**（Codex 特别纠正了先前 `git grep` 的误报为空）；Hermes / Claude / Codex 在 readme 与 PRD 中有据。

## 三、这对优丁意味着什么（诚实研判）

### ✅ 能做的：把 Hermes 变成 AionUi 的一个 ACP Agent

**路径**：给优丁后端加一个 **ACP 端点** → 写一个 AionUi 扩展指向它。

```
AionUi（租户/运营者的桌面客户端）
   │  ACP (http 或 stdio)
   ▼
优丁 Hermes 的 ACP 端点（🆕 待建）
   │  内部仍走既有链路
   ▼
decompose() → AiTask → ExecutorRegistry → 9 个执行器
```

**这正好落地你说的「前端 Harness 作为租户外层 + 万能皆可插 + 拆解要求」**——AionUi 是**现成的前端壳**，Hermes 是**后端大脑**，中间用 ACP 连。

**工作量**：优丁侧需实现一个 ACP 服务端（把 `decompose()` + 任务查询映射成 ACP 的 session/prompt 语义）；AionUi 侧只需一个 `acp-adapters.json` 条目（**改配置，不改代码**）。

### ⚠️ 不能做的：直接嵌进优丁的 Web 后台

**AionUi 本体是 Electron 桌面应用**（`packages/desktop/`，入口 `process/index.ts` + `renderer/main.tsx`），另有同源的 WebUI（`scripts/webui.ts`）与移动端（Expo/React Native）。

**它不是可以 `<iframe>` 进来的 Web 组件。** 所以：
- ❌ 别指望把它塞进 `frontend/admin`
- ✅ 它是**独立伴侣应用**：租户/运营者装它，通过 ACP 连优丁 Hermes

### 📌 另一个价值：它是「外层编排」的参考实现

AionUi 的扩展机制（`aion-extension.json` 可 contributes：`acpAdapters` / `mcpServers` / `assistants` / `agents` / `skills` / `themes` / `settingsTabs`）**正是「万能皆可插」的成熟做法**——值得参照它设计优丁自己的插件契约。
