# 智能化规划·分步实施（基于全量盘点的家底定制）

> 版本 V1.0 ｜ 2026-09-06 ｜ 前置阅读：《系统功能拓扑全景》《架构设计-智能编排内核》《架构设计-智能化获客系统组合方案》
> 核心思路：**你不是缺功能——500+ 服务模块九大域全都有。你缺的是把现有零件"总装"的顺序。** 以下每一步都用现有资产，每一步都产出可演示的东西。

---

## 总路线图（六步，前两步是还债，后四步是增值）

```
第0步 止血清障(2周)  →  第1步 数据主线(3周)  →  第2步 编排内核(4周)
                                                      ↓
                       第4步 三引擎全链(6周)  ←  第3步 首个智能场景(3周)
                                                      ↓
                                        第5步 学习闭环+市场开放(持续)
```

---

## 第 0 步：止血清障（2 周）——还"抖音式开发"的债

**目标**：让现有系统"说真话"——每个按钮背后都是真实现，每个服务要么在岗要么下岗。

| # | 动作 | 明细 | 验收 |
|---|---|---|---|
| 0.1 | 假实现清零 | site-ai/publish 假发布接真链；payment Mock 通道打标隔离；talking_stick 加鉴权 | 全系统 grep 无"硬编码成功返回" |
| 0.2 | 断链接线 | site_builder/product_images/sitemap 三个未挂载模块注册；10 个孤儿服务逐个判决（接线/归档） | openapi 数字对齐；孤儿清单清零 |
| 0.3 | 重复合并 | 健康检查 4→1；performance 同名 2→1；积分/token_ledger 归一；news 双注册；ssl 前缀修复 | 每个能力只有一个入口 |
| 0.4 | 双栈对齐 | 全部 P0 用例在 SQLite+PG 两栈跑通（RLS 决策：PG 栈启用） | 两栈行为一致报告 |
| 0.5 | 回归资产化 | 把历轮 *_verify.py 套件接成一键回归（tests/ 已有基础） | 一条命令全量回归 |

**为什么排第一**：不清障，后面每一步都在烂地基上加层——第 4 步的三引擎全链会把这些假实现放大成客户投诉。

---

## 第 1 步：数据主线（3 周）——把六个"各写各的"拧成一股

**目标**：五个真相源 + 一条账本，所有域只读写它们（详见拓扑文档 §5 的断裂点地图）。

| 真相源 | 动作 | 完成标志 |
|---|---|---|
| 产品库 | AISiteEngine 生成时强制读产品库全量（图/参数/认证），不再只拿 product_name | 官网产品区=真实产品库 |
| 内容资产 | news/content_master/案例/百科 之上建统一"内容资产视图"（只读聚合，不迁移表） | 发布台能选任何来源的内容 |
| 线索库 | 统一进线口径：webhook/邮箱像素/RFQ/表单全部写 unified 层+标记渠道 | 归因报表渠道数字对得上 |
| 站点内容 | 发布真落库（替代假发布），i18n 镜像同事务 | 发布后域名可访问+截图回执 |
| 租户上下文 | tenant_id 注入审计：所有写操作强制来自登录态（防伪造） | 越权测试通过 |
| 任务账本 | TaskControl 在 PG 真库冒烟（轮16-22 遗留红线），决定开关灰度 | PG 上影子双写 30/30 |

**这一步没有新功能，但它是"统一"二字的本体。** 验收铁律见组合方案 §8。

## 第 2 步：编排内核（4 周）——任务图跑起来

按《内核设计》P1+P2：三契约 schema、图落 ai_tasks、执行监督器（并行/重试/on_fail 降级）、执行器注册中心（DeerFlow/Accio/ai_engine/Browser/n8n 收编）。
**验收**：拔掉 DeerFlow 容器，任务图自动换路完成交付；断电重启图续跑。

---

## 第 3 步：首个智能场景（3 周）——"传图建站"端到端

选**建站链**作为第一个任务图场景（客户价值最直观、断点已被 0.1/1 修掉）：

```
客户传图(n8n/网页) → 图：图片入库→产品建档→AI建站(真数据)→多语→GEO资源→真发布→截图取证→n8n通知
```

- L1 图模板先行（Hermes 按模板出图，DeepSeek 只填参数）
- 全链每节点落 ai_tasks，客户后台可见"我的建站任务"进度条
- **这是第一次"组合"给客户看的东西**：一句话需求 → 系统自己跑 8 步 → 交付官网+预览截图

---

## 第 4 步：三引擎全链（6 周）——把 5 张核心图全部点亮

按《组合方案》§5 的五张图逐个上：建站图(已done)→内容图→外呼图→回流图→调研图。
每张图的验收都是**业务指标**而非技术指标：
- 内容图：一周自动产出 20 篇文章+10 个视频，全部经 brand_guard+人审后分发
- 外呼图：100 个目标客户全自动走完"搜索→建档→开发信→发送→追踪"
- 回流图：官网询盘 5 分钟内进 CRM 并派发跟进任务
- 调研图：DeerFlow 报告自动成为内容选题源

## 第 5 步：学习闭环 + 市场开放（持续）

- L2 动态出图：Harness 上线（DeepSeek 对没见过的意图实时出图，schema 校验兜底）
- L4 经验回流：归因数据（哪封信转化/哪类内容引流）注入 Planner 上下文——系统越用越准
- 技能市场：能力按执行器契约开放注册，按调用量计费分成
- 组合矩阵回归测试集 + 故障注入（持续）

## 里程碑与依赖关系（防跳步）

```
0止血 ──→ 1数据主线 ──→ 2内核 ──→ 3建站场景 ──→ 4三引擎 ──→ 5学习/市场
   │            │            │
   │            └─ RLS/PG 决策在这里做（0.4 产出）
   └─ 若跳过 0：3/4 步每张图都会踩一遍假实现和断链
```

**给第一次做系统的你三条原则**（比步骤更重要）：
1. **以后每接一个"抖音上看到的智能插件"，先问三个问题**：数据进我的真相源了吗？执行落我的账本了吗？能力按契约注册了吗？——答不上来就不接。
2. **每一步只做"让已有零件通电"，不再新增零件**。500 个模块够你组合出任何竞品的功能了。
3. **每 30 天给客户/自己演示一次端到端场景**，演示不过的步不算完成。
