## 五、6 节点循环链路审计（核心）

用户要求的链路：

```
n8n（触发）→ Hermes（调度）→ ECC（提供知识/SOP）→ DeerFlow（深度执行）→ n8n（自动化分发）→ 用户（接收结果）
```

### 5.1 各节点存在性核查

| 节点 | 状态 | 证据 |
|------|------|------|
| **n8n（触发）** | ✅ 存在 | `app/services/n8n/__init__.py`（25 行）+ `trigger.py`（异步触发 + 指数退避）+ `webhook.py`（HMAC-SHA256 签名验证）+ `workflow_registry.py` |
| **Hermes（调度）** | ✅ 存在 | `app/services/hermes/` 63 文件，含 `runtime.py` / `registry.py` / `command_center.py` / `flywheel_workflow.py` |
| **ECC（提供知识/SOP）** | ✅ 存在（**本项目自建**） | `app/services/hermes/ecc_expert_panel.py`（8 位专家人格）+ `site_builder_ecc_pipeline.py`（ECC 流水线） |
| **DeerFlow（深度执行）** | ✅ 存在 | `app/services/ubrain/deerflow_job_service.py`（536 行）+ `deerflow_bridge.py`（轮 24-A 影子双写） |
| **n8n（自动化分发）** | 🟡 部分存在 | `n8n/trigger.py` 存在但**无分发路由**——触发 ≠ 分发 |
| **用户（接收结果）** | 🟡 通知链路未闭环 | 没有专门的"结果回传"模块，靠 `app/api/v1/` 通用 API |

### 5.2 链路成环性核查（核心偏差）

**审计结论**：6 节点中 **4 个已实现**（n8n 入口、ECC、DeerFlow、Hermes 调度），**2 个未闭环**（n8n 分发、用户回传）。

#### 偏差 #1：n8n（入口）→ Hermes（调度）—— **未直连**

- n8n 通过 Celery 异步触发 workflow
- Hermes 接收任务**通过 ubrain/deerflow_job_service.py**（不是直接）
- **偏差**：本应 n8n → Hermes，**实际是 n8n → ubrain → Hermes**
- **影响**：多了一跳，**审计时延 + 一次额外反序列化**

#### 偏差 #2：Hermes（调度）→ ECC（提供知识/SOP）—— **是单点调用**

- `ecc_expert_panel.py` 是 Hermes **内部**的子模块
- 8 位专家**只能被 Hermes 调用**，**不能被外部 n8n 触发**
- **偏差**：ECC 是 Hermes 的**私有资产**而非**公共服务**
- **影响**：不能复用——任何想用 ECC 专家的代码都得经过 Hermes

#### 偏差 #3：ECC → DeerFlow（深度执行）—— **链接松散**

- `site_builder_ecc_pipeline.py` **可能**会调用 DeerFlow
- **审计无法确认**——需读 100+ 行代码确认
- **审计假设**：通过 `ubrain/deerflow_job_service.py` 间接调用

#### 偏差 #4：DeerFlow → n8n（自动化分发）—— **缺失**

- DeerFlow 完成执行后**没有触发 n8n workflow** 的代码
- n8n 的 `trigger.py` 可用，但**没有挂点**让 DeerFlow 调用
- **影响**：闭环失败——结果无法自动分发

#### 偏差 #5：n8n（分发）→ 用户（接收）—— **缺失**

- n8n 触发后**没有"结果推送"模块**
- 用户接收到结果靠**主动轮询**（不是 webhook 推送）
- **影响**：UX 差——用户必须主动查询，不能被动接收

### 5.3 链路偏差示意图

```
实际状态（偏差版）：

n8n(trigger) ──→ ubrain ──→ Hermes ──→ ECC(私有)
                              │             │
                              ↓             ↓
                          DeerFlow ◄───(?)
                              │
                              ↓
                          [没有 n8n 触发]
                              │
                              ↓
                          [用户主动轮询 API]


期望状态（用户描述）：

n8n(trigger) ──→ Hermes ──→ ECC ──→ DeerFlow ──→ n8n(分发) ──→ 用户
       ↑                                                          │
       │                                                          │
       └──────────────── 反馈/确认 ◄──────────────────────────────┘
```

### 5.4 修复建议（按优先级）

| 优先级 | 动作 | 工作量 | 风险 |
|--------|------|--------|------|
| ★★★ | **偏差 #1**：让 n8n 直接调 Hermes（不经过 ubrain） | 中 | 中（涉及异步队列改造） |
| ★★★ | **偏差 #4**：DeerFlow 完成回调触发 n8n trigger | 中 | 低（trigger.py 已就位） |
| ★★ | **偏差 #2**：把 ECC 专家面板升级为可独立 import 的公共服务 | 大 | 中（需解耦） |
| ★★ | **偏差 #5**：加 webhook 推送结果给用户 | 中 | 中（鉴权 / 幂等） |
| ★ | 审计偏差 #3 | 小 | 无 |
