## 0. 一句话结论

获客闭环**零件极多、文档很细、诚实机制在**，但生产上仍是：

```text
「模板/演示线索 + 真模板开发信 + 人审不自动发 + 渠道多数未配真 API」
```

**不是**「已经全自动真获客」。细部真相见 §9 真伪矩阵。

## 2. 外呼/Accio 核心（我们自己的卖货飞轮，≠ 阿里 Accio）

### 2.1 `accio_sales_service.py`（约 784 行）

| 函数 | 输入→处理→输出 | 诚实点 |
|------|----------------|--------|
| **find_buyer_prospects** | NL → 解析地区/数量/品类 → 优先 `ai_find_customer_sidecar`，否则 **archetype 模板生成器**（distributor/contractor/epc/importer + 区域 ISO）；fit_score=`55+(idx%4)*8` | 恒 `human_verify_required:true`；免责：「公开 B2B 采购画像模板，非阿里站内实名」 |
| **outreach_letter_pack** | message + prospect_ids → **必须有产品画像** → **确定性模板信**（非 LLM）→ deliverability 富化 → 写 `outreach_draft` | `human_send_required:true`，**不发送** |
| **negotiation_draft** | 硬编码三轮双语（报价/压价/确认） | 不自动改价、不自动签约 |
| **confirm_outreach_send** | 审计确认 | 文案：「实际发信仍由人工在邮箱/IM 完成」 |

会调用：`trade_intel.blue_ocean`、`commercial_os_bridge.retrieve_insights_for_accio`、`tenant_memory.record_tool_use`。

### 2.2 渠道找客服务真伪

| 渠道 | 真伪 | 细节 |
|------|------|------|
| **Google CSE** | 有 Key 则真，否则 mock + 免责 | 无 Key 空结果诚实；snippet 无邮箱时可能编 `contact@domain` |
| **LinkedIn** | **演示/模板** | 编造 `{first}.{last}@{company}.com` + 假 evidence_url；channel_status 标 mock |
| **WhatsApp** | 可选真 Google 路径 + 明确 mock 回退 | 未配置：「该渠道未配置真实 API」 |
| **TikTok/Reddit/Quora** | 模板包 | channel_status: mock/coming_soon |
| **AI_Find_Customer Sidecar** | 外部 HTTP；生产禁 stub | `AI_FIND_CUSTOMER_ALLOW_DEV_STUB=0` 时拒 mock |
| **channel_status.py** | 渠道真相源 | 无凭证标 mock，避免「假渠道看起来像真的」 |

### 2.3 邮件栈

| 模块 | 行为 |
|------|------|
| email_send_service | **真发**：Resend/SMTP；无 Key → `success=false`「未配置邮件服务」，不假 sent |
| email_outreach_service | 状态机+幂等+像素；**门禁** `_outreach_gate_hold` 仅 `PIPELINE_GATES_ENABLED=1` 时强制首封人审；**默认关=直通** |
| email_tracking | open/click/reply 回写 |
| outreach_deliverability | 真启发式：spam 词表、主题分、国家→时区发送窗、RFC 邮箱校验 |
| email_quality + outreach_quality API | 质量评估、A/B、四步获客流程——**只分析不发送** |

## 3. 内层爱马仕编排（获客相关）

### 3.1 执行器

| 执行器 | 真相 |
|--------|------|
| **accio** | 真适配 accio_sales；`outreach.letter` **needs_approval=true** |
| **trade_ai_agent** | 曾 mock（假邮箱假 sent）已移除；现走 `adapters.tradeai`，缺 vendor → **failed 诚实**；WA needs_approval |
| **lead** | GeoLead；证据分 email+40/company+30/country+20/industry+10，**无证据不默认 0.5** |
| **research** | research.prospect 需公司名，走 DeerFlow |
| **deerflow** | outreach.letter→outreach_letter；prospect.enrich→buyer_research |

### 3.2 审批闸

- `task_control_supervisor`：`approval_required` 模式 → `wait_human` + `blocked_reason=approval_required:capability=…`
- **当前 L1 拓客图**：`approval_required=["outreach.letter"]`
- 建站图也含 accio outreach 节点，同样受闸

### 3.3 卖货飞轮 `flywheel_workflow.py`

```text
market_research(deerflow_job)
  → find_buyer_prospects
  → enrich_buyers_with_clean_and_osint（清洗+OSINT 抽样）
  → run_pipeline_after_deerflow
  → 可选 outreach_letter_pack 草稿
```

对外强制：`needs_confirmation` + `human_review_required`；品牌守卫把 Accio 脱敏成「获客执行/获客助手」。

### 3.4 现行 L1 拓客图（planner）

```text
n1 accio prospect.enrich  →  n2 accio outreach.letter
input_from: n1.output.leads
approval_required: outreach.letter
```

**缺口**：未强制 OSINT 节点、未强制海关交叉验证、未把「千人千面 LLM」接进此图（当前 letter 是确定性模板）。

### 3.5 孤儿图

`hermes/templates/outreach_scenario.py` 引用 **未注册** 的 `temporal_workflow` → 若走模板会被安全阀拒绝（死图）。

## 8. 细微操作细节（编排时必须知道）

### 找客

1. 先定 ICP：行业/规模/地区/买家类型（importer/distributor/contractor/retail/EPC）  
2. 多源：海关/提单 → Google → LinkedIn 决策人 → 社媒/WA → 官网询盘被动  
3. 去重进 ProspectLead / BuyerProspectLead  
4. **UI 必须展示 channel_status=mock**，禁止把演示行当真线索  

### 背调（OSINT）— 触达前

1. 公司存在 → 网络足迹 → 贸易足迹 → 规模 → 决策链 → 制裁  
2. 评分：匹配/邮箱可信/证据/联系人完整  
3. 低分进人工池；制裁阻断  

### 千人千面开发信

1. 背调信号开头 + 1 痛点 + 1 证据 + 低摩擦 CTA  
2. 非 LLM 路径=确定性模板；LLM 路径=ai_email_generator + RAG prospect_research + 质量 A/B  
3. 送达：SPF/DKIM/DMARC、时区窗、spam 扫描  
4. **首封人审**（当前 env 默认可能未开，上线前必须开 `PIPELINE_GATES_ENABLED=1`）  
5. 序列 D0→D3→D7→D14→断联信；禁 “just checking in”  

### 触达通道

- Email：真发仅 Resend/SMTP 配置后  
- WhatsApp：官方 API；模板审核；养号；高风险人审  
- confirm_outreach_send **≠** 系统代发  

### 回流与成交

询盘分级 A–D → 多语言回复 → BOQ/核价 → PI → 定金 → CI/PL → 物流 → 经验回流  

### 计费

获客节点吃 Token + 可选 IP 槽位；SaaS 为底座

## 11. 建议补齐清单（按优先级）

### P0 安全与诚实

1. 生产开启 `PIPELINE_GATES_ENABLED=1`（首封人审）  
2. 前端强制展示 mock 渠道与 `human_verify/send_required`  
3. 禁止 `contact@domain` 进入自动发送队列  

### P1 编排完整（对齐第二大脑 08）

4. L1 拓客图扩节点：`osint/score → customs_crosscheck → letter(千人千面) → quality → wait_human → send_seq`  
5. 删除或重写孤儿 `outreach_scenario.py`（去掉 temporal_workflow）  
6. 把 customs-lookup / negotiation / boq-calculator / inquiry-triage **落成 SKILL.md**（服务已在 backend）  

### P2 真数据与真通道

7. Google CSE / 邮件 SMTP / 海关 Sidecar / TradeAI vendor 配置清单进 `.env.example`  
8. Accio 草稿 → EmailOutreach **显式接线**（仍人审后发）  
9. LinkedIn/社媒：无 OAuth 保持 mock，不升级叙事  

### P3 经验环

10. 渠道质量、reply_rate、成单回写 ExperienceBizOutcome  
11. mock 流量 `simulated=true` 不进技能晋升  
12. 统一 hermes JSON 经验 → evolution PG 真源
