§2 结论更正（前期判断中被推翻的部分）

前三路测绘中，有若干结论基于非活跃代码根（主要备份/上线网站/backend 的旧世代）或基于「读 main.py 是否有 include_router」的间接推断。经运行态取证后推翻如下 7 项。保留此节是为避免后续会话再被同一批错误结论误导。
原结论裁定取证与正确事实
「后端 159 个业务路由模块未注册 → 前端 /api/v1/* 全域 404」推翻该结论来自读取非活跃 backend 根（`主要备份/上线网站/backend` 的旧世代清单）。活跃根（W）用 `app/api/v1/routes/__init__.py` 的 FIX-30 auto_discovery（pkgutil 扫描 ~180 模块）注册，`app.main` 在整包导入完成后调用 `register_routes()`。实测运行态 `/openapi.json` 有 1801 条唯一路径 / 2053 个方法级端点 / 1800 条在 `/api/v1` 下 / 255 个 tag；本机自检脚本本次实测 带 ROUTE_PREFIX 的模块 70 个，命中 69 个。
「后端未挂 `/api/v1` 全局前缀」推翻`app/main.py:639` 为 `app.include_router(api_router, prefix="/api")`，且 `routes/__init__.py` 的 router 自带 `prefix="/v1"`，合成 `/api/v1`；前端 `api/index.ts:9` 的 `baseURL = VITE_API_BASE || '/api/v1'` 与之吻合。
「后端无 CORS 中间件」推翻`app/main.py:10` 导入、`:560-561` `app.add_middleware(CORSMiddleware, ...)`；全文件共 20+ 中间件（安全头/CSRF/限流/租户/GZip 等，`:560-621`）。
「前端 `window.$api` 未注入导致视图取不到实例」推翻全仓检索 `window.$api` 与 `$api.` 于活跃 admin 源码零命中，`main.ts` 也没有对应插件——即该机制从未被使用，不构成断链。
「对外站 3000 是纯 SPA，服务端 SEO/GEO 注入全失效」部分推翻该判断成立于 M 根 Vite 版（`主要备份/上线网站/frontend/index.html` 16 行）。但当前 3000 实际服务的是 W 根 Nuxt 版：curl 实测返回 200 / 42493 字节，HTML 内含 `__NUXT__`、`/_nuxt/`、nuxt entry.js，且正文已含 SSR 渲染后的中文内容 → 服务端注入在运行态是生效的。
「AEOS / Hermes 双 executor 是 mock 桩」推翻生产路径走 `backend/app/services/aeos_hermes_service.py:202-222` 的 `HermesService` 真实现；同名的另一份为跨库双实现，不是桩。
「`routes/im_routing.py` 是 IM 路由实现之一」推翻该文件不存在。活跃实现是顶层 `backend/app/api/v1/im_routing.py`（`ROUTE_PREFIX="/im-routing"`，`:31`）。`generate_im_link` 的双份定义确实存在，但分别在 `app/api/v1/im_routing.py:162` 与 `app/services/im_locale_service.py:166`。
