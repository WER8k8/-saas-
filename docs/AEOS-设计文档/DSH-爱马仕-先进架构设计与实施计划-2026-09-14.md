# DSH × 爱马仕 · 先进架构设计与实施计划

> **命名法定**：外层 **DSH** · 内层 **爱马仕** · 插件层执行器/航道  
> **公式**：外层 DSH（技能包+意图）→ 内层爱马仕（智慧调度指挥分派）→ 任意编排插件 = 无限可能场景  
> **依据**：`DesktopHermes动态自由组合装配总案-2026-09-14` + 代码实测差距 + 本计划  
> **日期**：2026-09-14

---

## 0. 设计原则（先进但不空转）

| 原则 | 含义 |
|------|------|
| **单指挥权** | 一切业务图只由内层爱马仕编译与派发；DSH/前端/n8n 只产意图或做出口适配 |
| **契约优先** | 执行器声明 capability + JSON Schema 输入输出；无契约不进图 |
| **约束生成** | LLM 出图必须过 JSON Schema + 能力白名单 + 拓扑阀，失败降级不炸链 |
| **先模板后自由** | L1 确定性航道保证商用；L2 动态拼图在约束下解锁长尾 |
| **诚实执行** | 桥未配/表为空 → `failed`/`degraded`，禁止假成功 |
| **可回放** | 图与节点状态全落库，进程挂了能从 `ai_tasks` 恢复 |
| **最小改动** | 优先在 `planner_service` / `harness_gateway` / `executors` 扩展，不平行造第 13 套引擎 |

```json

  "source": "L1_template|L2_llm|L3_minimal|L2_hybrid",
  "strategy": "standard",
  "policies": {"max_parallel": 4, "degradation": "skip", "budget_cap": 0.5},
  "nodes": [{
    "id": "n2",
    "executor": "trade_ai_agent",
    "capability": "prospect.scrape",
    "depends_on": ["n1"],
    "input": {"country": "SA", "product": "rockwool"},
    "input_from": {"keywords": "n1.output.keywords"},
    "persona_ref": "agency://arabic_trade_officer",
    "sop_ref": null,
    "skill_refs": ["prospecting"],
    "approval_required": false,
    "compensation": {"action": "none|delete_draft|release_hold"},
    "on_fail": "abort|skip"
  }],
  "injected_assets": [{"type": "skill", "id": "boq-calculator", "version": "1.2.0"}]
}
```

#### 执行器能力契约（Registry 扩展）

每个执行器在 `capabilities` 上增加：

```python
CAPABILITY_CONTRACTS = {
  "prospect.scrape": {
    "input_schema": {...},   # JSON Schema
    "output_schema": {...},
    "side_effect": "read_only|external_send|billing",
    "compensable": False,
    "requires_env": ["TRADEAI_BASE_URL"],
  }
}
```

爱马仕 Governor 在派发前校验 `input_from` 指向的上游字段是否满足下游 `input_schema`（JsonPath 解析后再校验）。

## 2. 外层 DSH · 组件级设计

### 2.1 Intent Normalizer（新）

- **位置**：`backend/app/services/hermes/intent_normalizer.py`（或 `dsh/intent_normalizer.py`）
- **技术**：
  1. 规则/词典快路径（品类、国家、Incoterms、数量）— 零成本
  2. 可选 LLM：JSON Schema 约束输出（`response_format=json_schema` / 工具调用）
  3. 失败 → 保留 `raw_text`，`intent="raw_text"`，走模板关键词或 L3
- **输出**：合法 `IntentEvent`，**禁止**在 normalizer 里调业务 API

### 2.2 Skill Router（升级现有 `skill_pack_loader`）

**混合检索（生产级推荐）：**

| 通道 | 做法 | 用途 |
|------|------|------|
| BM25/关键词 | 已有 match_skill_pack 强化 | 快、稳 |
| 向量 | SKILL.md chunk → embedding（复用 Qdrant @6333） | 同义改写 |
| 规则加权 | scene_type → 默认技能包（如报价→boq-calculator） | 兜底偏置 |
| 租户偏好 | 历史成功经验提升权重 | 个性化 |

- top-k 默认 3–5，**禁止 76 个全量塞 Prompt**
- 输出 `skill_refs[]`，正文只注入 `metadata + 能力摘要 + 关键约束（≤N tokens）`

### 2.3 Context Compiler

把 Skill/SOP/Persona 编译成 **有预算的上下文包**：

```text
budget_tokens = min(plan.budget, model_context * 0.4)
优先级：执行器契约 > 选中 Skill 摘要 > SOP 关键条 > Persona 一句 > 历史经验 hint
超预算 → 截断并写入 injected_assets.truncated=true
```

### 2.4 Plan Compiler（DSH 核心，升级 `planner_service`）

采用 **三级 + 混合**（比纯 LLM 更先进、更稳）：

```text
L1  Template Library
    - 声明式 YAML/JSON 场景图（不再是散落 Python 函数）
    - 路径：backend/app/services/hermes/templates/*.yaml
    - 字段：match(scene/keywords/actions) + graph 骨架 + 参数槽
    - 支持「参数槽插值」：product/country/quantity 注入节点 input

L2  Constrained LLM Compile（约束编译）
    - System Prompt = 已注册执行器+capability+Schema 摘要 + top-k Skill
    - 输出仅 JSON TaskGraphSpec
    - 解析失败 / validate_graph 失败 → 不采用
    - 可选：把 L1 骨架给 LLM 做「节点增删改」而非从零生成（更稳）

L3  Minimal / Degraded
    - 单节点 deerflow 或 ai_engine 直答，明确 fallback 标记

L2+ Hybrid（推荐主路径）
    L1 命中骨架 → 按 required_actions/skill_refs 在骨架上「插拔节点」
    → validate_graph → source=L2_hybrid
```

**实现落点**：`planner_service.decompose()` 保持 API，内部改为 Template Store + Hybrid Compiler。

### 2.5 DSH Runtime（可选增强）

- 保留 `deepseek-harness` 作为**长程复杂规划沙箱**（多日研究、超长上下文）
- 日常主路径不强制走 dsh.exe；通过 MCP（`hermes_mcp_server`）让 DSH 调用爱马仕 `generate_plan` 工具
- 客户端：`deepseek_harness/client.py` 已懒加载 — 只在 `scene_type ∈ 长程集` 时调用

## 3. 内层爱马仕 · 组件级设计

### 3.1 Graph Governor（强化 `validate_graph` + supervisor）

校验流水线（全部失败则拒图）：

1. JSON Schema（TaskGraphSpec）
2. 执行器 ∈ Registry
3. capability ∈ 契约表
4. Kahn 防环 + 节点数上限
5. JsonPath 可解析 + 上游 output 字段满足下游 input_schema
6. side_effect=external_send/billing 的节点必须 `approval_required=true` 或租户策略允许
7. budget 合计预估 ≤ budget_cap（可用历史均值）

### 3.2 状态机（事件溯源式，可恢复）

```text
pending → validating → ready → dispatching → running
    ↘ rejected
running → wait_human → running
running → succeeded | failed | skipped
failed → compensating → compensated | compensation_failed
任意态 → cancelled（租户/超管）
```

- 持久化：`ai_tasks` + `plan_id/node_id/depends_on/state/attempt/external_ref`
- Worker 崩溃：`dispatching/running` 超时 → 回 `ready` 重派（幂等键 = `plan_id+node_id+attempt`）

### 3.3 Data Bus（JsonPath 契约化）

- 解析 `n1.output.xxx` 时校验存在性与类型
- 缺失时按节点 `on_fail`：skip 或 abort，**不静默空参调用**
- 敏感字段（手机号、PI 路径）打标，日志脱敏

### 3.4 Dispatcher

- 沿用 `hermes_task_bridge.ROUTERS` + `hermes_node:<executor>`
- 执行器实现统一：`async def execute(ctx) -> ExecutorResult`
- `ExecutorResult`: `{status, output, evidence[], external_refs[], cost}`

### 3.5 Side-effect Ledger（先进必备）

```python
class SideEffect(Base):
    plan_id, node_id, kind,  # whatsapp|email|publish|payment|pi_pdf
    idempotency_key,
    external_ref,           # 消息 id / PDF 路径 / 订单号
    state                   # prepared|committed|compensated|failed
```

- 补偿只针对 `committed` 且 `compensable=True`
- 不可补偿（已发出的 WhatsApp）→ 记 `compensation_failed` + 人工工单

### 3.6 Metering

- 每节点：token、耗时、模型、executor
- 汇总到租户三轨：SaaS / Token / IP 槽位（billing executor 读台账）

### 3.7 Experience Flywheel（受控）

- 成功图 → 存 `experience_store`：scene → 模板 id / 节点集 / 成功率
- **只影响**：L1 模板排序权重、Hybrid 插拔候选、审批阈值建议
- **禁止**：自动改生产 Prompt 无版本；自动关闭安全阀
- 变更走 `ExperienceProposal` → 人审/金丝雀 → 再上线

## 4. 插件层设计

### 4.1 执行器分层实现标准

```text
Level A  纯函数/本地（content 草稿、BOQ 计算）— 必须真
Level B  内网服务（GoodJob、TradeAI base URL）— 配置后真
Level C  外网/平台（publish、WhatsApp）— LIVE 或诚实 STUB + wait_human
```

每个执行器 README 一行：`Level ? · requires_env · side_effect · compensable`

### 4.2 DeerFlow 2.0

- 主路径：`deerflow_executor` → 本机逻辑 / Lite
- 增强：`ubrain/deerflow_sidecar` HTTP（Gateway 8001）
- 输出：`meta.deerflow_version` + `meta.degraded=true|false`
- 爱马仕节点 output 必须透传 meta，禁止装成 2.0 全量

### 4.3 n8n

- **薄出口**：Hermes 节点 `n8n.notify` / `n8n.dispatch`
- 注册表 `workflow_registry`：workflow 必须绑定 `capability` + `schema`
- 禁止：n8n 内部长业务分支绕过爱马仕（只留 IO/通知/第三方）
- 场景资产：`docs/scenes/*.yaml` 与 L1 模板同构

### 4.4 四航道（商用最小集）

| ID | 意图 | L1 模板名 | 关键节点 |
|----|------|-----------|----------|
| A | 市场调研/上架 | `research_content` | research → deerflow → content |
| B | 找客户/私域 | `outreach_wa` | lead/trade_ai → score → engagement(WA) wait_human → inbox.classify |
| C | 询盘报价履约 | `fulfillment_quote` | inquiry → goodjob PI/BOQ → billing → logistics.track |
| D | 复合 | `hybrid_mena_launch` | A∩B∩C 参数化骨架 + Hybrid 插拔 |

## 8. 技术选型建议（与现仓兼容）

| 点 | 建议 | 理由 |
|----|------|------|
| 图模板 | YAML + Pydantic 校验 | 比 Python 散函数可审、可热更 |
| LLM 出图 | ModelGateway + JSON Schema/工具调用 | 已有网关与记账 |
| 向量检索 | Qdrant（已有配置位） | Skill 语义召回 |
| 队列 | Celery 现状 | 不换栈 |
| 状态 | PostgreSQL ai_tasks | 已是统一任务面 |
| 追踪 | OTel spans（core 已有痕迹） | plan/node 维度 |
| 前端 | Admin 内嵌编排页 | 不先做重桌面 |

**不建议**：再引入新编排框架（Temporal 全量替换等）——现有爱马仕内核方向正确，缺的是契约与接线。

## 9. 风险与门禁

| 风险 | 缓解 |
|------|------|
| L2 幻觉出幽灵执行器 | Governor 白名单硬拦 |
| Prompt 注入窃取租户数据 | Intent 与租户上下文隔离；Skill 只读注入 |
| 外发骚扰 | external_send 强制 wait_human |
| 假成功 | Level 声明 + 自检扫描 fake |
| 双引擎回潮 | AGENTS 锁：编排只经爱马仕 |
| 软著/文档混名 | 叙事只用 DSH / 爱马仕 |

## 10. 成功度量（Reality Gate）

```text
M1 零件齐套     verify_executors + selfcheck 全绿
M2 航道商用     A/B/C 各 ≥1 条 E2E 真跑，source 与 degraded 可见
```
