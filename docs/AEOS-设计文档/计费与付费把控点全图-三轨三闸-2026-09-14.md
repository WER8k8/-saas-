
# 计费与付费把控点全图（第二大脑 + 代码对齐）

> **北极星**：获客莫比乌斯 + 商业正循环（体验好→付费→续费）  
> **第二大脑口径**：三轨计费 = SaaS 订阅 + AI Token + 静态IP/指纹槽位  
> **代码现状**：meter_events/token_ledger/wallet/payment/finance_ledger 已在；B-5 生产闸门曾拍板「暂开=影子计量」

## 1. 三轨收费模型（钱从哪来）

| 轨 | 收什么 | 何时扣 | 代码方向 |
|----|--------|--------|----------|
| **轨1 SaaS** | 套餐月/年费（档位权限） | 开通/续费 | saas_billing PlanTier、license、subscription_countdown |
| **轨2 Token** | AI 生成/翻译/推理 | 调用时预扣或后计量 | token_ledger、meter ai_generation、Token Wallet |
| **轨3 槽位** | 静态IP/指纹/WA账号 | 按月租/按量 | egress slots、billing 节点 |

可选加轨（已有设计痕迹）：获客积分（信用分+消耗分，product_commerce）、API 调用次量。

## 2. 付费闸门地图（哪里必须「把控」）

```
┌ 租户侧支付 ─────────────────────────────────────┐
│ 选套餐/充值 Token/加购槽位 → payment 下单        │
│ → 支付成功 → license/钱包/槽位激活               │
│ → 失败/超时 → 不激活（禁止先用后假装已付）        │
└────────────────────────────────────────────────┘
┌ 使用侧计量 ─────────────────────────────────────┐
│ 每次 AI/发布/外呼/槽位占用 → meter_event 幂等埋点 │
│ → 汇总 → token_ledger / finance_ledger           │
│ → 对账 reconcile（误差报告）                     │
└────────────────────────────────────────────────┘
┌ 拦截侧闸门 ─────────────────────────────────────┐
│ 套餐能力不足（plan_gate）→ 拒绝或升级引导        │
│ Token 余额 0 → Wallet Guard：任务挂起/402        │
│ 槽位无可用 → 分配失败诚实提示                    │
│ 订阅过期 countdown → 催缴/降级策略               │
└────────────────────────────────────────────────┘
```

## 3. 细胞级把控清单（收费点 × 动作 × 闸）

### 3.1 应收费动作（meter / 扣 Token / 占槽）

| 动作 | 计费轨 | 埋点方向 | 闸门 |
|------|--------|----------|------|
| AI 文章/视频脚本 | Token | ai_generation | plan 额度 + wallet |
| 多语翻译/配音 | Token | ai_generation | 同上 |
| 建站生成 | Token（可套餐包月） | ai_generation | plan_gate |
| 千人千面开发信 | Token | ai_generation | 额度；人审不另收乱价 |
| 外发邮件/WA | 次量/积分或含套餐 | api_call / lead 类 | 限频+余额 |
| 多平台发布 | 次量 | content_publish | 配额 |
| OSINT/背调 | 次量或 Token | api_call | 配额 |
| 拓客线索 | 积分/次量 | lead_generated | 配额 |
| 静态IP/指纹槽 | 轨3 | finance/subscription | 分配前查付费状态 |
| 订阅本身 | 轨1 | payment/license | 到期 countdown |

**红线（代码已强调）**：计费复用既有 wallet/token_ledger/payment/finance_ledger，**禁止再建平行账本**。

### 3.2 必须把控的「钱相关错误」

| 风险 | 把控 |
|------|------|
| 白嫖（免费无限用） | 生产开真闸：Token 0 挂起；套餐能力校验 |
| 双扣 | meter event_key 幂等 |
| 少扣/漏埋点 | 编排节点 billing.meter 强制路径（履约图定金/尾款） |
| 假支付成功 | payment 服务端金额校验（历史：曾修 amount=1 漏洞）+ PAYMENT_STRICT_VERIFY |
| 双记账混乱 | 双记账开关默认关；生产只选一种账本策略 |
| 超卖槽位 | 分配事务 + 状态机 unassigned→active |
| 到期仍全功能 | subscription_countdown + plan_gate |
| 退款/争议 | payment 状态机 + 人工工单，不自动乱改 ledger |
| 租户串账 | 所有 ledger 强制 tenant_id |

## 7. 生产开闸路径（关闭白嫖模式）

历史结论：计量代码可跑，**B-5 真扣闸曾默认关（影子）**。把控顺序：

1. **影子计量**跑通：meter 全埋点 + reconcile 误差≈0  
2. **只读账单**：租户可见消耗，不强制拦  
3. **软拦**：余额低提醒，不挂起  
4. **硬拦**：Token 0 → 402 挂起（Wallet Guard）  
5. **支付真验**：生产 PAYMENT_STRICT_VERIFY=1  
6. **对账巡检**：每日 meter vs ledger  

每步有开关可回滚；禁止无对账直接硬拦。

## 8. 与莫比乌斯 / 商业正循环

```
计费准确 + 账单可解释 + 超额有出路
  → 租户信任付费
  → 收入 → 数据与能力
  → 获客更准 → 成交↑ → 更愿付费
```

把控目标不是「扣得狠」，而是 **扣得准、拦得住、说得清、续得久**。
