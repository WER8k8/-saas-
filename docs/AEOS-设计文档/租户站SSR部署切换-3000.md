# 租户站 SSR 部署切换（3000 端口去 SPA 化）

> 关联：2026-09-19《国内工程建材租户-获取排名与UJ帮成交总报告》阻塞项 A（SPA 失效）
> 根因：3000 当前跑的是 `主要备份/上线网站/frontend/` 的 **Vite SPA 空壳**（index.html 仅 16 行，纯 `#app` 挂载点），
> 百度/爬虫拿不到正文与 JSON-LD → 排名全失。worktree `上线网站.worktrees/.../frontend/` 是 **Nuxt 3.12.4 SSR**，依赖已装，本就具备 SSR 能力。
> 结论：问题不在代码层 SSR 关闭，而在**部署用了 SPA 副本**。切到 Nuxt SSR 产物即可，工作量远低于重写。

## 一、验证现状（先确认再切）

```powershell
# 在 3000 宿主上执行
curl -s http://127.0.0.1:3000/tenant | findstr /C:"<div id=\"app\">" /C:"application/ld+json"
```

- 若只看到 `<div id="app">` 且**无** `application/ld+json` → 确认是 SPA 空壳（现状）。
- 切完后重跑：应看到 `<h1>` 正文 + `<script type="application/ld+json">` 的 Organization/Product Schema。

## 二、构建 Nuxt SSR 产物（worktree）

```powershell
cd "C:\Users\Administrator\Documents\上线网站开发完成\上线网站.worktrees\agents-install-vscode-cline-deploy-strix\frontend"
# 依赖若未齐：npm install
npx nuxt build        # 产出 .output/ （Nitro 服务端，SSR 首屏含完整 HTML + JSON-LD）
```

## 三、切换 3000 绑定

1. **停掉**当前服务 `主要备份/上线网站/frontend` 的 Vite dev/preview 进程（占用 3000 的那个）。
2. **起 Nuxt SSR 产物**（二选一）：
   - 独立 Nitro：`node .output/server/index.mjs`（默认监听 3000，按 nuxt.config `devServer.host/port`；生产用 `HOST`/`PORT` 环境变量覆盖）
   - 或 `npx nuxt start`（需保留构建产物）
3. 保持原有反代/端口映射不变（仍是 3000 对外）。

## 四、回归验收

- [ ] `curl 3000/tenant` 返回含 `<h1>` 与 `application/ld+json` 的完整 HTML
- [ ] `curl 3000/tenant/faq`、`/tenant/test-reports`、`/tenant/parameters`、`/tenant/certifications`、`/tenant/supplier-onboarding`、`/tenant/brand-guide` 均 SSR 出 H1 + 正确 `<title>`/description
- [ ] 百度/Google 站长工具「抓取渲染」可见正文（不再空 #app）
- [ ] 不破坏 ENV-LOCK-01：PG@5433 / Redis@6379 / n8n@5678 连接正常（仅换前端静态/SSR 层，后端不动）

## 五、备选 C 路径（不重建，仅反代注入 SEO 元信息）

若暂不能切构建，可在 3000 反代层对 `/tenant/**` 注入 canonical/hreflang/desc 占位——但**仅为止血**，正文仍空，不解决排名本质。优先级低于本方案。

> 注意：本机派生长驻进程会被回收，服务须由指挥官在本地终端拉起；上步骤为交付给指挥官执行的清单，非 AI 代为常驻。
