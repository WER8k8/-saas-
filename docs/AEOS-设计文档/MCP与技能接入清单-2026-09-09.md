## 2. MCP 服务器接入清单

按对**本项目组装**的价值排序。来源：魔搭 MCP 广场（9,200+ 服务器，支持托管 SSE 或本地 stdio）与开源社区。

### P0-1 · PostgreSQL MCP（最高价值）

**为什么**：项目最大的验证盲区就是「数据库状态说不清」——225 / 229 / 239 三个表数并存、RLS 是否生效、`admin_roles` 是否 0 行，全靠读文件猜。接上之后这些都能当场查。

**推荐**：`Postgres MCP Pro`（crystaldba）——自托管 PG 的生产级选择，带真实 SQL 解析 + 只读事务 + 超时，附索引调优与健康检查。
**明确不要用**：Anthropic 归档的 `@modelcontextprotocol/server-postgres`（2025-05 归档，有未修补的多语句注入漏洞，可逃逸只读事务执行 `DROP SCHEMA`）。

配置（本地 stdio，uvx）：

```json
{
  "mcpServers": {
    "postgres-youding": {
      "command": "uvx",
      "args": ["postgres-mcp", "--access-mode=restricted"],
      "env": {
        "DATABASE_URI": "postgresql://mcp_reader:<只读密码>@127.0.0.1:5433/youding_dev"
      }
    }
  }
}
```

**安全前置（必须）**：在 PG 里建一个**专用只读角色**，不要用应用凭证：

```sql
CREATE ROLE mcp_reader LOGIN PASSWORD '<强密码>';
GRANT CONNECT ON DATABASE youding_dev TO mcp_reader;
GRANT USAGE ON SCHEMA public TO mcp_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO mcp_reader;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO mcp_reader;
```

备选：**DBHub**（Bytebase，MIT，默认只读 + 行数限制 + 超时，支持多引擎）。

### P0-2 · Playwright MCP

**为什么**：官网 3000、admin 5174 的实际渲染效果、四壳是否正常、登录是否破锁——这些只能靠真浏览器验证。项目本身有 Browser Runtime 子系统（Playwright），接上后可端到端对照。

**推荐**：Microsoft 官方 `@playwright/mcp`（基于无障碍树，动作确定、无需视觉模型）。

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest", "--headless", "--viewport-size=1440x900"]
    }
  }
}
```

安装浏览器：`npx playwright install`。首次调用时**要明确说「用 Playwright MCP」**，否则我可能走 Bash 跑 Playwright。

1. **决定装哪些 MCP**：至少装 P0 的两个（PostgreSQL + Playwright）。装完重启应用生效。
