# 模型无关的续作规约 · 怎么让任何模型把项目续下去而不跑偏

> **面向**：任何接手优丁项目的 AI / IDE / 智能体，**不论能力强弱**。
> **解决的问题**：设计意图漂移 —— 换个模型做的事就不是你要的了；而你不想每次重新讲一遍。
> **一句话**：**别指望模型变聪明，要把任务降维成不需要聪明。**

---

## 一、先认清：漂移不是"模型笨"，是意图没被固化

**设计意图漂移 = 意图只存在于你的脑子里和对话里，对话一结束就没了。** 模型只能用「自己的理解」填空，于是每个人填得都不一样。

漂移分三层，用药不同：

| 层 | 表现 | 现有药 |
|---|---|---|
| **事实漂移** | 端口/库/配色/数字说错 | ✅ 《后端·官网强制索引-必读》 |
| **硬锁漂移** | 破坏登录/四壳/主色/八子系统 | ✅ `AGENTS.md` §3 六大硬锁 |
| **意图漂移** | 做的事不是你要的 | ⚠️ **缺药 → 本文件** |

**关键认知**：前两层靠「文档写清楚」能治，第三层治不了 —— 因为**意图不是事实**，没法"查证"。
治它只有一个办法：**把意图转成可执行的约束**。

---

## 二、四道防线（把"请不要"变成"做不到"）

### 防线①：契约 —— 接口固定，实现自由

模型可以在契约内自由发挥，但**改不了契约**。

- 已有：`schemas/hermes_orchestration.py`（`IntentEvent`/`TaskGraph`/`TaskNode`/`GraphPolicies`/`ExecutorResult`）
- 已有：`BaseExecutor` 的 `get_executor_name()` + `run()` + `get_capabilities()`
- 效果：**任何模型写的执行器，只要满足契约就能插上**；不会因为风格不同就跑不起来。

### 防线②：白名单 —— 不允许的，物理上做不到

**这是最强的一道**。不是"请不要用别的执行器"，而是**用不了**：

| 白名单 | 位置 | 效果 |
|---|---|---|
| 执行器白名单 | `planner_service.validate_graph()` | 引用未注册执行器 → 图直接判非法 |
| 能力白名单 | `ExecutorRegistry.all_capabilities()` | 编造能力 → 被拦 |
| 单证类型白名单 | `trade_document_bridge` | `doc_type` 非法 → 抛错 |
| 审批模式 | `GraphPolicies.approval_required` | 命中即挂起等人审 |

**设计原则**：能做成白名单的，绝不写成"文档提醒"。提醒会被忽略，白名单不会。

### 防线③：门禁 —— 跑不过就不算完成

**没有门禁的"完成"是自称的。** 现在项目已有：

| 门禁脚本 | 检查什么 | 跑不过说明什么 |
|---|---|---|
| `tools/fake_scan.py` | 假数据/假成功 | 有假交付 |
| `tools/verify_executors.py` | 执行器契约 + 能力声明 | 插件不合规 |
| `tools/smoke_orchestration.py` | 模板一致性 + 能力覆盖（+`--live` 端到端） | 链路不通 |
| `tools/capability_ledger.py` | 串联率 | 接没接上 |
| `tools/capability_tags.py` | 归属标签（未归类须 0） | 有模块没归属 |
| `tools/orchestration_selfcheck.py` | 编排门禁 | 编排不自洽 |

**要求下一个模型**：改完必须跑，**跑不过不许声称完成**。

### 防线④：留痕 —— 推翻了什么必须写下来

`docs/00-会话产出串联索引-*.md` 的核心价值不是"列文件"，是**记录「事实怎么变来的」**。

- 旧结论被推翻 → 在索引里标出
- 换了实现路径 → 记下为什么换
- **否则下一个人会拿旧结论当现状**

## 三、怎么让"弱的模型"也能做对：把任务降维

**不要让它"设计"，让它"照单执行 + 跑门禁"。**

项目已经把这四件事准备好了：

| 问题 | 谁回答它 |
|---|---|
| **我该做什么？** | `docs/能力台账/归属表.md`（每个模块该不该串）+ `docs/能力串联接线图-2026-09-10.md`（每步怎么串） |
| **我做到哪了？** | `tools/capability_ledger.py` 的串联率 + `smoke_orchestration.py` 结果 |
| **我该照谁写？** | `backend/app/services/hermes/executors/site_builder_executor.py`（**模板**，新执行器照它抄） |
| **我不许做什么？** | `AGENTS.md` §3 六大硬锁 + 上面的白名单 |

**所以一个能力一般的模型的正确工作方式**：

```
1. 打开 docs/能力台账/归属表.md → 找 to-orchestrate 的模块
2. 挑一个 → 照 site_builder_executor.py 的样子写个新的
3. 在 executors/__init__.py 注册一行
4. 跑 tools/verify_executors.py → 必须 9→10 合规
5. 跑 tools/capability_ledger.py → 串联率必须涨
6. 跑 tools/fake_scan.py → HIGH 必须 0
7. 更新 docs/00-会话产出串联索引 → 查漏未收录须 0
```

**全程不需要"聪明"，只需要"照做 + 验门"**。这就是降维。

## 四、不重复讲的办法：把"我要干什么"写成文件

**你只要说一次，之后让模型自己去读。** 三个文件回答三类问题：

| 你想说的 | 已写在 |
|---|---|
| 「我要做的这套东西是什么、边界在哪」 | `AGENTS.md`（入口契约）+ `docs/全链路串联设计-总纲-2026-09-10.md`（架构 × 业务链） |
| 「具体还差哪些、怎么补」 | `docs/能力台账/归属表.md` + `docs/能力串联接线图-2026-09-10.md` + `docs/50平台接线台账-2026-09-10.md` |
| 「以前谁做过什么、什么被推翻了」 | `docs/00-会话产出串联索引-2026-09-10.md` |

## 六、一句话总结

**防止意图漂移，不靠模型自觉，靠三件事**：

1. **意图写进文件**（不靠口头传）
2. **约束做成白名单**（不靠文档提醒）
3. **完成以门禁为准**（不靠自我声明）

**模型可以换，能力可以差，但这三样不变，做出来的东西就不会跑偏。**
