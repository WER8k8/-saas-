## 一、先定三句话

1. **下一阶段不是「再写一堆系统」，是把已有系统逐条接线并让链真正跑通。** 当前端到端未实跑（所有验证是静态的）。
2. **阶段的推进顺序 = 依赖关系，不是喜好。** Phase 2 必须先过，因为它证明地基；Phase 3 依赖 2；Phase 4 依赖 3。

## Phase 2 · 端到端打通（现在，Codex 正在做段 B）

**目标**：不是新增代码，是把已有的链在真实环境跑起来。

**动作**（对应总表段 B）：起服务（`start-lan.bat`）→ 跑 `smoke_orchestration.py --live` → 确认 `graph_source=L1_template` / `node_count≈7` / `dispatched=true` → 回查 `ai_tasks` 落库 → 修任何 bug → 把结果写回实作记录。

**验收门禁**：
```
python3 tools/smoke_orchestration.py --live   # 全绿
python3 tools/verify_executors.py             # 9/9
python3 tools/fake_scan.py                    # HIGH 0
```

**⚠️ 重要提醒**：
- 数据库业务表**全空**（229 表仅 11 张有数据）。冒烟卡在「没有数据」时先跑 `backend/seed.py` 灌种子。
- **遇到报错不要慌，那是最有价值的活**——说明有真 bug，修掉它就是成果。

**出口条件**：`smoke --live` 全绿 + 结果回写。**在此之前，Phase 3 的任何执行器接入都属于「在没验过的主干上继续盖楼」。**

## Phase 3 · 主链完整（Phase 2 通过后）

**目标**：业务链 18 步，每一步都有真实执行器承接；前端能走通「发一句话 → 看到任务图 → 看到每步结果」。

**三个子批次**（对应总表段 C + N 剩余）：

| 批 | 接什么 | 依托 | 为何此时 |
|---|---|---|---|
| 3a | `inquiry` / `product` / `logistics`（总表段 C） | 符号已核为真 | 最贴近入站→履约主干 |
| 3b | `media` / `seo` / `lead`（业务链 ④⑤⑩⑪） | `media_factory` / `seo_matrix` / `lead_*` | 内容获客主干 |
| 3c | `crm` / `engagement` / `forum` / `research` / `order` | `crm_pipeline` / `opportunity` / `social_*` | 商机与履约后端；`order` 需先补路由 |

**验收门禁（每批过完）**：
```
python3 tools/verify_executors.py             # 执行器数增长且 全合规
python3 tools/capability_ledger.py            # 串联率逐批上升（目标 ≥40%）
python3 tools/fake_scan.py                    # HIGH 0
tools/smoke_orchestration.py （静态）全绿
```

**此时才做**：段 D（TODO P0 核心基础）——因为 P0 里很多是「把散模块挂上主链的补全」（P0-01/02/03 挂路由、P0-04 stub SEO 替换、P0-12 track API 真拉取）。**P0 放这，不做在 Phase 2 前**，避免堆文档不开跑。

**出口条件**：业务链 18 步关键路径（建站→内容→分发→养号→获客→CRM→物流）各有一个真执行器且串联率 ≥40%。
