> **根因**：当前沙箱环境对 npm registry（registry.npmjs.org / npmmirror / cdn.npmmirror）**仅有 TLS 握手、无法传输实际数据**（实测 2.4MB tarball 120s 超时失败）。PyPI 出口正常（后端 Python 依赖已成功安装），但所有 npm 源均不通。因此所有基于 npm 的前端/SEO/Workers 服务无法在本环境安装依赖启动。

## 二、本次为启动后端所做的修复

1. **SQLAlchemy 与 Python 3.13 不兼容**  
   项目锁定 `sqlalchemy==2.0.29`，在 Python 3.13 下导入即报 `TypingOnly` metaclass 错误。已将 SQLAlchemy 升级至 `2.0.52`（仍兼容 alembic 1.13.1）。

2. **缺失 `app.data.load_platforms`**  
   `app/services/publish_service.py` 引用了 `from app.data import load_platforms`，但该函数在本 worktree 快照中完全未定义，导致 `app.main` 无法导入。已新建 `backend/app/data/__init__.py` 提供最小化实现（默认返回空列表，可经 `platforms.json` 覆盖），发布相关接口优雅降级。

3. **`async_cache_decorator` 参数不兼容**  
   `app/core/cache.py` 的装饰器只接受 `expire=`（timedelta），而 `lead_tools.py`、`product_commerce.py`、`domain_registry` 用 `ttl=`（秒），导致这 3 个路由模块在自动发现时被跳过。已为装饰器增加 `ttl: int | None` 别名参数，模块现已正常注册。

4. **环境配置**  
   已生成 `backend/.env` 与 `backend/config/dev/.env`（Postgres/Redis 指向本机 Docker、JWT 密钥、DEV 模式），以及 `frontend/.env`、`seo-backend/.env`、`seo-admin/.env`。
