## 1. L-Pro 商业化门禁清单（物理落点已核）

L-Pro 是 SITE-DESIGN-01 的高阶建站档位（`premium-b2b-v1`）。门禁不在文档里，而是**代码函数**，可机读、可复跑。

### 1.1 门禁判定的唯一真源

| 项 | 物理落点 | 说明 |
|----|----------|------|
| 档位常量 | `app/services/site_l_pro_service.py` L11-12 | `L_PRO_TEMPLATE_ID="premium-b2b-v1"`、`L_PRO_TEMPLATE_TIER="L-Pro"` |
| 发布门禁函数 | `validate_l_pro_publish_gate(site_content, environment="development")` | 唯一判定入口，返回 `{ok, publish_ready, p0, p1, issues}` |
| 门槛阈值契约 | `.project/site-design-target.json → publish_gate.thresholds` | 缺省 `min_products_with_images=3`、`min_spec_fields_per_sku=3`（`publish_gate_thresholds()` 读取） |
| 档位识别 | `is_l_pro_site_content()` | `templateTier==L-Pro` / `visualEditor.templateId` / `templateId` 三路径之一命中即 L-Pro |
| 填充逻辑（非造版式） | `apply_l_pro_site_pass()` | Hermes 建站后处理，绑模板 + 补 L-Pro 槽位；默认 3 个 productItems（Standard/Enhanced/OEM Custom） |

### 1.2 P0 门禁项（任一不满足 → `publish_ready=False`，不可对外发布）

| # | check | 规则 | 严重级 |
|---|-------|------|--------|
| 1 | `site_content` | 缺 site_content 即 P0 | P0 |
| 2 | `template` | `templateId` 必须为 `premium-b2b-v1` | P0 |
| 3 | `product_count` | `productItems` 数量 ≥ `min_products_with_images`(默认3) | P0 |
| 4 | `product_images` | 带真实图片（非 `data:` 前缀）的产品数 ≥ 门槛 | P0 |
| 5 | `product_specs` | 每个产品 specs 数 ≥ `min_spec_fields_per_sku`(默认3) | P0 |
| 6 | `about` | `about.aboutText` 非空 | P0 |
| 7 | `contact` | 至少一个联系方式（phone/email/whatsapp/wechat/qq） | P0 |
| 8 | `mock_mode` | `meta.probe_mode=="stub"` 或 `meta.mode=="mock"` 即不可发布（v3 F18 不造假） | P0 |

P1（不影响 `publish_ready` 但需整改）：`visual_editor_html`（L-Pro 应走 premium shell，GrapesJS html 不作默认面）、`contact_placeholder`（production 下 email 仍 `example.com`）。

### 1.3 门禁红线（与硬锁一致性）

- 门禁只判定、不生成/不绕过；`apply_l_pro_site_pass` 只补槽位不改版式，与「禁硬编码、不造假」一致。
- P0 第 8 项直接服务 v3 F18 / B1 原则：模型/Executor/Provider 可换，**租户隔离、计量、证据、审计不能换**——mock/stub 站内容禁止以 L-Pro 身份发布。

## 2. 计费 Phase1「影子计量」落点（三轨）

三轨 = SaaS 订阅 + AI Token + 静态 IP/指纹槽位。Phase1 目标：**只留痕、不扣减、不阻断**（影子模式），把计量埋点先跑通，生产计费闸门另行拍板（人工阻塞项，列 backlog 不进门禁）。

### 2.1 计量主路径（可机读、双开关闭环）

| 环节 | 物理落点 | 现状 |
|------|----------|------|
| 统一埋点服务 | `app/services/billing/meter_event.py` `MeterEventService` | 7 类 append-only 埋点（`ai_generation/content_publish/lead_generated/rfq_created/api_call/export/video_job`），`event_key` 幂等去重 |
| 汇入账本 | `aggregate_to_billing()` | ai_generation→`token_ledger_entries` 扣减；其余 6 类→`finance_ledger_entries` 营收；`aggregated_at` 防重 |
| 对账 | `reconcile()` | 计量侧 vs 账本侧，`error_free` 结论；不平即 `[对账告警]` 主动报（审计 P2） |
| 配额闸门 | `evaluate_ai_quota()` → `plan_gate_service.evaluate_ai_quota` | 套餐能力 + AI 额度只读判定 |
| 旁路异步埋点 | `emit_ai_generation_best_effort()` | SessionLocal + `asyncio.to_thread`，异常全吞，**绝不阻断主链路**（总纲 §4.6 红线） |
| 模型网关成本账 | `app/services/model_gateway/ledger.py` `CostLedger` | 每次 LLM 调用写 `model_call_ledger`（迁移 095），`record()` 异常吞掉不影响主链路 |

### 2.2 Phase1 影子模式开关（当前默认状态 = 全关 = 影子）

| 开关 | `app/core/config.py` 行 | 默认 | 含义 |
|------|------------------------|:----:|------|
| `TASK_CONTROL_ENABLED` | L74 | `False` | meter_events 计量→token_ledger 扣减主路径。关=**只埋点不扣减**（影子计量） |
| `MODEL_CALL_LEDGER_AGGREGATE_ENABLED` | L78 | `False` | model_call_ledger→token_ledger 聚合闸门。关=旁路账本也不聚合 |
| 双记账互斥（轮24 防护） | 注释 L75-78 | — | 两路径**二选一**启用；切记账主路径须「先关 `TASK_CONTROL_ENABLED` 再开 `MODEL_CALL_LEDGER_AGGREGATE_ENABLED`」，防止 token_ledger 双重扣减 |

**结论（B1 口径）**：Phase1 Shadow 已落盘——埋点/对账/配额/旁路写入代码全部在位，`aggregate_to_billing` 扣减由 `TASK_CONTROL_ENABLED` 闸住，默认 `False` 即「只留痕不扣减、不阻断主链路」。这与 v3 F18「旁路记录、绝不中断主链路」一致。

### 2.3 Hermes 计费执行器（可被任务图调度的计费节点）

`app/services/hermes/executors/billing_executor.py`：`BillingExecutor`（node.executor=`billing`），能力 `billing.meter` / `billing.invoice`。
- 降级契约：`record_meter_event` import 失败 → 返回 `status="succeeded", metered_degraded=True`（诚实降级，不假 success，v3 F18）。
- 注意：其内 `from app.services.billing.meter_event import record_meter_event` 指向**模块级函数名**；当前 `meter_event.py` 暴露的是类方法 `MeterEventService(...).emit_*`，无模块级 `record_meter_event`。该 import 会走 `except ImportError → metered_degraded` 降级分支——**行为正确（降级诚实），非阻断**。质量部门核验时如判定计费需真跑，须补一个模块级 `record_meter_event(db, tenant_id, event_type, amount)` 适配薄封装，使降级路径转正。列为 **backlog B-6**（人工/后续，不阻塞门禁）。
