陷阱二：等宽数字（实测宽度差）

码表每帧改数字，若字形宽度不等宽，数字块会左右抖动。 font-variant-numeric: tabular-nums 就是为这件事存在的。下面用同一字体实测「11」与「88」的宽度。

判据：开启 tabular-nums 时，两组数字（等宽对等宽）宽度差应为 0。 若关掉后出现非零差值，就说明这个属性是必需的——这正是「码表丝滑」的隐性前提。

05

接线与两个已修缺陷

// ① 模板 ref：注意 vue-echarts 上 r.chart 才是 ECharts 实例，r 本身不是
<v-chart ref="trendChartRef" :option="trendChartOption" autoresize />

// ② 取哪条 series 的值 —— 这是业务问题，助手不猜
const { activeIndex, activeValue, bindWhenReady } = useChartCursor<number>((info) => {
  const v = trendData.value[info.dataIndex];
  return typeof v === 'number' ? v : null;
});

// ③ 绑定：图表被骨架屏 v-if 包着 + 实例初始化晚一帧 → 有界重试（上限 30 帧）
watch(trendChartRef, (el) => {
  if (el) void bindWhenReady(() => trendChartRef.value);
}, { flush: 'post' });

// ④ 码表：有游标读游标，无游标读均值 —— 两者共用一个码表，切换时才看得到翻滚
const readoutTarget = computed(() => cursorValue.value ?? trendAverage.value);
const readoutText = useCountUp(() => readoutTarget.value, { changeDuration: 220, decimals: 0 });
本轮修掉的缺陷问题修法
useCountUp 的 enabled 语义 旧写 if (!enabled) return; → 不仅不动画，连数值都不更新（首次永久停在 0）。语义应为「不做动画」而非「不更新数字」 改为直接落值并置 started
useChartCursor 的 ChartLike.on 声明为可选属性 → chart.on(...) 被判可能 undefined（TS2722）。而 resolveChart() 本就只在 on 是函数时返回对象 把接口的 on 改成必需（修声明，而不是到处加断言）

刻意不做：数字翻滚的 prefers-reduced-motion 降级。 理由是数字翻滚属于「原地换值」、无空间位移，不触发前庭不适；降级反而会丢掉「读数已变化」这一提示。
