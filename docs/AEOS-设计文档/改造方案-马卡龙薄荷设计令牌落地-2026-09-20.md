## 0. 一句话结论

**本次改造的本质是「收敛」，不是「新增」。**
项目已有 266 个 `--uj-*` 令牌与 30 个 `yd-*` 组件，问题不是"没有体系"，而是**三套真源并行 + 主色硬编码 320 处**。
因此策略是：**新增一个纯增补令牌层 → 收敛三套真源 → 用令牌替换硬编码**，而不是重建组件或另起一套样式。

## 5. 改造方案（四步）

### Step 1 · 令牌层收敛（G1）—— 地基

**新增一个纯增补层，不动既有层**：

```
main.ts 引入顺序（现状 → 改造后）
  ant-design-vue/dist/reset.css
  design-tokens-v3.scss
+ design-tokens-v4-macaron.scss   ← 新增（纯增补）
  adaptive-tokens.scss
  mint-glass-shell.scss
  ...
```

**v4 层只做三件事**：
1. **新增**马卡龙五色（各带 `-50` 浅底 / `-300` 马卡龙 / `-700` 正文深版三角色）
2. **新增**语义深版 / 玻璃导航档位 / `--uj-text-link` / 阴影档位 / 画布底
3. **新增** `--uj-brand-strong` —— **按 `:root[data-uj-accent='…']` 作用域分别派生**（platform/client `#367469`、agent `#0f766e`、partner 待核验）

> 为什么纯增补？新增变量名不会与既有 266 个令牌冲突，对现有界面**零视觉影响**，因此**零回归风险**，且可整文件删除回滚。

**收敛三套真源**（Batch 0）：
- Tailwind：`primary.500` → 读 `var(--uj-brand)`
- AntD：`antTheme.token.colorPrimary` → 读同一变量
- 收益：改一处令牌，三处同步

### Step 2 · 导航层玻璃化（G2）

- 在 `layout/index.vue` 根容器铺 `--uj-canvas-grad` + 2~3 个马卡龙光斑（**玻璃的底衬，必做**）
- 顶栏 / 侧栏加**局部作用域类** `.uj-glass-nav { backdrop-filter: var(--uj-glass-nav-blur); … }`
- **关键**：作用域必须避开 `mint-glass-shell.scss` 的禁用选择器（`.shell .content-area` / `.yd-page-body` / `.ant-card` / `.yd-panel` / `.yd-stats-card`）——**导航层不在禁用列表内**，可安全启用
- 送检模式（`.cert-watermark-wrap`）下加一条覆盖：`.uj-glass-nav { background: var(--bg-surface); backdrop-filter: none; }`

### Step 3 · 内容层令牌化（G3 + G4）

- 对接既有 `yd-*` 组件，替换其内部硬编码与旧阴影
- **用 `--uj-brand-strong` 承载实心按钮**（白字 5.44 ✅AA），替代直接用 `--uj-brand`（白字仅 3.30）
- **用 `--uj-text-link` 承载正文品牌色文字/链接**（6.01 ✅AA），替代直接用 `--uj-brand`（仅 3.17）
- 语义色：色块用既有主色，**文字一律用 `-strong` 深版**
- 核对涨跌色是否已符合 C7（**当前实现口径待核验，见 §8-H4**）

### Step 4 · 硬编码存量衰减（G5）

- 跑 `check-hardcoded-colors.mjs` 拿基线（约 320 处）
- 按目录分批替换，每批 ≤10 文件
- 每批后跑一次扫描，记录计数 → **计数曲线即进度**

## 8. 风险登记

| # | 风险 | 影响 | 应对 |
|---|------|------|------|
| **H1** | **Tailwind 颜色改用 `var()` 后，透明度修饰符失效**（如 `bg-primary-500/50` 不再生效） | 大量既有 class 视觉变化 | **P0 Spike 先验证**。方案 A：改用 `rgb(var(--uj-brand-rgb) / <alpha-value>)` 格式（需同时提供 RGB 分量变量）；方案 B：Tailwind 侧保留 hex，只在 SCSS 侧收敛 |
| **H2** | **AntD Vue 4 的 `colorPrimary` 可能不接受 `var()`** —— 它内部用算法派生 hover/active，需能解析颜色值；`fontFamily: 'var(...)'` 能work **不代表**颜色能 | 主色失效或派生色错乱 | **P0 Spike 先验证**。可行则用；不可行则保持字面量，但**从单一 TS 常量导出**，仍算单源。AntD v5 的 `theme.cssVar` 模式可作备选 |
| **H3** | partner 壳主色 `--uj-shell-partner-accent` 实际值未知，`brand-strong` 无法派生 | partner 壳按钮白字可能不达 AA | 待核验后补；**v4 文件中已留 `TODO` 注释，未臆造色值** |
| **H4** | 现有涨跌色实现口径未知（可能为欧美「绿涨红跌」） | 与中国习惯（C7）冲突 | 核验 `dashboard.vue` 与相关组件后再改，**不盲改** |
| R1 | 320 处硬编码一次性替换风险高 | 大面积视觉回归 | 分批 ≤10 文件，逐批回归 |
| R2 | 玻璃在低端设备掉帧 | 性能退化 | 仅导航层（≤3 处），已符合既有"每屏玻璃上限"约束 |
| R3 | v4 层引入后与 `admin-2026-global.scss` 潜在冲突 | 样式意外 | 已确认该文件**不定义 `--uj-*`**，为组件样式层，无令牌冲突 |
| R4 | 三套真源收敛后，某处仍留旧字面量 | 局部色漂移 | `check-token-single-source.mjs` 作为门禁 |
