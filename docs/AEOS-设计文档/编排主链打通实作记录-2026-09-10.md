## 零·补 · 契约补齐（2026-09-10 第三轮）

### 缺口一：`GraphPolicies` 定义了但**从未被读取**

设计文档 §契约二 定义了 `max_parallel` / `budget_cap` / `approval_required` / `degradation`，
但实测 `advance_plan()` 里**连 `policies` 都没引用** —— 四个字段全部空设。

**已补三重闸门**（`task_control_supervisor.advance_plan`）：

| 闸门 | 行为 | 向后兼容 |
|---|---|---|
| **并发** `max_parallel` | 本轮派发数达上限即留到下一轮 | 未配置 = 不限制 |
| **审批** `approval_required` | capability 命中模式 → 节点状态置 `wait_human`，挂起等人审 | 未配置 = 不拦 |
| **预算** `budget_cap` | 已耗 ≥ 上限 → 后续节点置 `paused` 并记 `blocked_reason` | 未配置 = 不熔断 |

模式匹配支持 精确 / 前缀通配（`publish.*`）/ 全量（`*`）三种写法；
**写错模式（漏通配）不命中** —— 宁可漏挂起，不误放行敏感操作（已 8/8 单测验证）。

### 缺口二：Executor Contract（能力声明）未实现

`base.py` 原只有 `get_executor_name()` + `run()`，**没有能力声明** ——
导致拆解器只能靠**硬编码白名单**猜能力，加执行器必须改 planner 代码。

**已补**：
- `BaseExecutor.get_capabilities() -> {capability: spec}`（spec 含 desc/input/output/cost/needs_approval）
- `ExecutorRegistry.all_capabilities()` 聚合全量能力，**带重名冲突检测**（先注册者优先 + 告警，不静默覆盖）
- **9 个执行器全部声明能力，合计 21 个**
- `planner_service.known_capabilities()` 改为**优先读注册表声明**，硬编码仅作兜底

> **效果**：加执行器 = 写文件 + 声明能力，**planner 零改动** —— 这才叫「万能皆可插」。

**顺带发现的能力冲突**：`content.create` 被 `content` 与 `deerflow` 同时声明（已告警，注册表保留先注册者）。

## 一、打通的那条线

```
前端「任务图」页（agent-hub/task-graph）
   │ 用户输入一句话：「帮我建站并推广」
   ▼ POST /api/v1/orchestration/tasks/from-intent
① planner_service.decompose(IntentEvent)
   ├─ L1 模板匹配（只产出**已注册执行器**的节点）
   ├─ L2 LLM 出图（走 ModelGateway，reasoning 能力）
   └─ L3 最小兜底（单节点，绝不出假图）
   ▼ 三道安全阀：① 执行器白名单 ② 拓扑治理 ③ 能力白名单
② TaskGraph（plan_id + nodes + policies）
   ▼ parse_graph_to_tasks()   ← 这个函数**此前无调用方**，现接上
③ AiTask：hermes_plan 父任务 + N 个 hermes_node:<executor> 子任务
   ▼ advance_plan()   ← 依赖判定 + JsonPath 注入 + 派发
④ Celery → dispatch_ai_task → ROUTERS / ExecutorRegistry
   ▼
⑤ 执行器执行（site_builder / deerflow / accio / …）
   ▼ 回写 output_json → 递归推进下游 → n8n 出站
```

1. **旧 L1 模板全是坏的**——`templates/site_build_scenario.py` 引用的执行器 `seo_matrix` / `ai_engine` / `bullmq_seo_backend` / `n8n_webhook` **一个都不存在**；`outreach_scenario.py` 还引用了不存在的 `temporal_workflow`。这些图一跑就崩。**新 planner 只产出已注册执行器，并有静态检查保证。**

4. **`persona_ref` 被静默丢弃**——`hermes_task_bridge.py:171` 向 `TaskNode` 传该字段，但 schema 无此定义。实测 pydantic v2 默认 `extra='ignore'` → 不崩，但人设特性悬空。
