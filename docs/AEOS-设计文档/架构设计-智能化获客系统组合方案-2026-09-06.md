# 智能化获客系统·组合方案（业务主线版）

> 版本 V1.0 ｜ 2026-09-06 ｜ 上游文档：《架构设计-智能编排内核-任务图驱动-2026-09-06》
> 回答一个问题：**这些强大的开源组件，到底怎么组合成一个"智能化获客系统"。**

---

## 1. 先说破：为什么"个个都强大，组合不起来"

三个根因，都不是组件的错：

1. **缺数据主线。** 官网、新闻、视频、SEO/GEO/AEO、获客、CRM——这些环节用的数据各写各的表（实测：建站用 tenants.settings、新闻用 news_articles、产品用 products、线索用 lead_*）。组件再强，数据不互通，就只能是七个孤岛工具。**粘合剂不是代码，是"租户业务真相源"这一份数据。**
2. **缺调度内核。** n8n/Hermes/DeerFlow 每个都有自己的任务概念（workflow/job/task），互相不认识。没有统一的"任务图"翻译层，组合只能靠人肉粘代码——粘一处断一处（这就是"AI 建站是笑话"的原因：site-ai/publish 假发布、建站路由没挂载、图片不自动带入）。
3. **被官网宣传误导了预期。** DeerFlow 官网演示的是"深度研究一台机器跑通"——但那是它自己 demo 数据的闭环；ECC 展示的是专家面板——但那是知识不是执行器；n8n 展示的是千种集成——但每个流程要人手搭。**它们都只提供"零件"，拼装图（编排内核+数据主线）必须自己造。** 这不是你选错了，是所有组合这些项目的公司都要造的，造出来就是壁垒。

---

## 2. 智能化获客系统全景：一个底座 + 三个引擎 + 一个大脑 + 一个市场

```
                        ┌─────────────────────────────────────┐
                        │   租户业务真相源（唯一数据底座）        │
                        │   产品库 · 品牌素材 · 内容库 · 线索库   │
                        │   配额账本 · 失败经验库                │
                        └──────────────┬──────────────────────┘
                                       │ 全部引擎只读写这一份
        ┌──────────────────────────────┼──────────────────────────────┐
        │                              │                              │
 【阵地引擎：等客来】            【外呼引擎：主动找】             【回流引擎：接住并转化】
 租户独立官网（产品/新闻/视频）    Accio：找买家→建档→开发信        询盘/RFQ → CRM 管线
 SEO：Google 收录排名            DeerFlow：市场深度调研           跟进任务自动派发
 GEO/AEO：让 ChatGPT 等AI         内容引擎：新闻/视频批量生产       成交/流失 → 经验回流
 推荐你（llms.txt/JSON-LD）       n8n：多平台分发+定时             （喂回大脑，越用越准）
        │                              │                              │
        └──────────────────────────────┼──────────────────────────────┘
                                       ▼
                    【大脑】DeepSeek Harness 出图 → Hermes 调度 → ECC 供方法
                            → 执行器干活（DeerFlow/Accio/建站/浏览器）→ TaskControl 记账
                                       ▼
                    【市场】技能插件市场 = 第三方能力按执行器契约注册，即插即用
```

**一句话业务模型**：阵地引擎让客户**找到你**（SEO/GEO/AEO 是三条不同的"被找到"通道）；外呼引擎让你**找到客户**；回流引擎把两头汇进 CRM **变成钱**；大脑让三个引擎**自己会干活**；市场让能力**无限扩展**。

## 3. SEO / GEO / AEO 的区分（很多人混为一谈，你是三个都要的）

| | SEO | GEO | AEO |
|---|---|---|---|
| 面向 | Google/百度 传统搜索 | 生成式引擎（Google AI Overviews 等） | 问答引擎（ChatGPT/Perplexity/豆包） |
| 问题 | "保温材料厂 排名第几" | AI 搜索摘要里**引用你**了吗 | 用户问 AI"推荐一家欧盟认证保温材料厂"，**它推荐你吗** |
| 你的系统里 | seo_matrix、rank_check、baidu_webmaster、sitemap | geo-score、llms.txt、JSON-LD | ai-crawler 中间件（识别 GPTBot 等，注入语义载荷）、ai_visibility |
| 共同依赖 | **同一份 site_content + 产品库** | 同左 | 同左 |

**这就是"统一"的价值**：一份高质量的站点内容，三条通道同时受益；内容烂，三条通道一起死。所以 AI 建站是地基中的地基。

## 4. AI 建站急救方案（地基工程，最优先）

"是笑话"的四个实锤（实测）→ 四步修复：

| # | 问题 | 修复 | 完成判据 |
|---|---|---|---|
| 1 | 内容是 LLM 编的+模板兜底，空泛不统一 | **产品库为唯一真相源**：建站时强制从租户产品库拉真实产品/参数/图片/认证，LLM 只做"组织与翻译"，不做"编造" | 生成的官网产品区 = 产品库实拍图和真实参数 |
| 2 | 图片不自动带入 | 生成管线第 2 步"产品建档→站点装配"自动带图（设计文档 P1 已含） | 客户传 5 张图，官网出现 5 张 |
| 3 | `/site-ai/publish` 假发布 | 接真实发布链：site_content 落库 → domains 绑定 → 门户可访问 → Browser Runtime 截图回执 | 发布后浏览器打开域名真能看到站 |
| 4 | site_builder/product_images 路由未挂载 | 注册进 routes/（半天工作量） | openapi 里能看到这两个模块 |

**修完的标准**：客户上传产品图和基本资料 → 30 分钟内拿到一个有真实产品、多语言、SEO/GEO/AEO 三通道就绪的官网 + 预览截图。这是整个获客系统的"入门产品"。

## 5. 组合公式速查（业务场景 → 任务图）

用《内核设计》的任务图机制，业务场景全部变成"图"。核心 5 张图：

1. **建站图**（阵地起点）：`图片上传 → 产品建档 → AI生成站点(产品库真数据) → 多语 → GEO资源 → 发布 → 截图取证 → n8n通知客户`
2. **内容图**（阵地燃料）：`选题(Hermes按市场热点/ECC内容SOP) → ai_engine写文章/媒体工厂做视频 → brand_guard → [人审] → 官网+多平台分发(n8n) → 收录/排名监控`
3. **外呼图**（主动获客）：`Accio找买家 → enrich补全 → AI开发信(ECC话术SOP) → brand_guard → [人审] → n8n发送 → 打开/回复追踪`
4. **回流图**（线索接住）：`官网询盘/RFQ/n8n外部表单 → 线索入库 → CRM管线 → 跟进任务自动派发 → 超时升级`
5. **调研图**（弹药补给）：`DeerFlow深度调研市场/竞品 → 报告 → 喂给内容图和外呼图的选题`

**获客回流的闭环**（你点名的）：回流图产生的线索，其"哪个渠道来、哪封开发信转化、哪类内容引流"全部记账 → 回流给大脑（L4）→ 下次出图时优先高转化路径。**这就是"智能化"和"自动化"的分水岭：自动化只执行，智能化会从结果里学习。**

## 6. 技能插件市场：让它长在执行器契约上

已有 `a2a_skill_marketplace_service` + `skill_store` 路由。组合方式：
- 每个技能 = 按《内核设计》契约三注册的一个能力（input/output schema + run() + 健康检查 + 成本）
- Hermes 出图时从注册表**动态发现**可用能力——客户装一个新技能（如"LinkedIn 自动化"），下一次出图就自动可用，不需要改代码
- 计费天然打通：每个节点已有预算/计量（meter_event），技能市场直接按调用量分成

## 7. 90 天落地路线（每 30 天见一次效果）

| 阶段 | 做什么 | 30 天末客户看到什么 |
|---|---|---|
| **第 1 月：地基** | AI 建站急救四步 + 数据主线（产品库/内容库/线索库统一 schema）+ 内核 P1（图落账本、执行监督器） | "传图 30 分钟出多语官网"可演示；L1 图模板上线 |
| **第 2 月：三引擎** | 建站图+内容图跑通（SEO 三通道就绪）；外呼图跑通（Accio+开发信+人审）；回流图跑通（询盘进 CRM） | 租户后台看到：官网被 Google/AI 引用、开发信发出、询盘进管线——全链路有账可查 |
| **第 3 月：智能化** | L2 动态出图（Harness 上线）+ L4 经验回流 + 技能市场开放注册 | 客户用自然语言下需求，系统自己选路执行；失败自动换路 |

## 8. 给你的三个验收铁律（防止再次"组合不起来"）

1. **一切新功能先问"数据写进真相源了吗"**——不进产品库/内容库/线索库/经验库的功能，一律不接。
2. **一切执行先问"这张图落账本了吗"**——没有 ai_tasks 记录、没有幂等键、不能回放的，视为假交付（项目自己的 no_fake_delivery 红线）。
3. **一切能力先问"按契约注册了吗"**——绕过注册表直连的集成（包括"临时先接一下"），上线前必须收编，否则三个月后又是一堆孤岛。
