```

      │
      ▼
match_skill_scored(db, query)          ← 打分路由（别名表 + 触发词 + 描述）
      │
      ▼

      ▼

      │
      ▼

```

若技能包不可用或未命中，才按原逻辑降级，并在 `reason` 中标注「已尝试技能包兜底」。

## 4. 使用方式

### 入库（幂等，可重复执行）

```python
from app.services.registry.skill_service import seed_skill_pack
stats = seed_skill_pack(db)          # {'discovered':76,'created':76,...}
seed_skill_pack(db, update_existing=True)   # 强制更新已存在技能
```

### 按意图自动匹配（自动智能判断调用哪个 skill）

```python
from app.services.registry.skill_service import match_skill_scored
hits = match_skill_scored(db, "buyer_research", top_k=3)
# → [(<Skill customer-research>, 100), (<Skill prospecting>, 75), ...]
```

## 5. 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `SKILL_PACK_SOURCES` | `business` | 扫描来源：`business` / `ecc`，逗号分隔 |
| `SKILL_PACK_DIRS` | 空 | 额外绝对路径（逗号分隔），优先级最高 |
| `SKILL_PACK_MAX_SOP_CHARS` | `6000` | SOP 正文截断长度 |
| `SKILL_PACK_MAX_TOKENS` | `8000` | 技能包执行时的 LLM 输出上限 |

## 6. 关键技术陷阱（已规避，勿回退）

1. **推理模型 token 陷阱**：成本模型 `qwen3.8-flash` 为 reasoning 模型，引擎默认 `max_tokens=2000~3000`，长 SOP 会把配额全耗在 reasoning（实测 `reasoning_tokens=3000`、`finish_reason=length`、**content 为空**）。必须放大 `max_tokens` 并截断 SOP。
2. **空 content 必须判失败**，不能拿空串冒充成功。
3. **发布态状态机** `draft → testing → active`，不能直接跳 `active`（抛 `IllegalTransitionError`）。
4. **别名表按位次递减给分**，否则同分排序退化成字母序。
5. **触发词 strip 尾随标点**，否则入库触发词形如 `"a/b test,"` 永远匹配不上。
6. **seed 需补发布**：已存在但非 active 的技能，重跑 seed 要补发布，否则残留永远修不好。
