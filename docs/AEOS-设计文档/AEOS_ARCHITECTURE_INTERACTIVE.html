03

WhatsApp → 核心后端 入站事件总线

P0 本轮已修复

原报告问题

Plugin 独立运行 Node.js @3100，与主后端缺少实时事件同步，CRM 无法实时感知入站消息。

本轮代码落地

  • app/services/whatsapp_event_bus.py：入站归一化 + event_bus 发布 + 落库
  • API：/api/v1/whatsapp-events/inbound|ack|connection|stats|recent
  • EventTypes 增补：whatsapp.message.received/sent/failed/ack
  • 支持 Baileys / Cloud API / 通用三种载荷；可选 WHATSAPP_INBOUND_TOKEN
  • CSRF 豁免机器 webhook 路径；单测 test_whatsapp_event_bus_and_evidence_analyzer.py

修复判定与接线说明

系统内入站事件总线已打通：Plugin 只需 POST 到 /api/v1/whatsapp-events/inbound，后端即时发布事件并可写 whatsapp_messages(direction=inbound)。 这是系统内通道总线，不是外挂业务桥。Plugin 侧 webhook 地址配置属运维接线。

04

Browser Runtime → 证据自动分析管道

P1 本轮已修复

原报告问题

双轨取证已收集证据，但缺少自动分析、异常检测、合规检查管道。

本轮代码落地

  • browser_runtime/evidence_analyzer.py：失败/阻断/降级/超时/合规检测
  • 合规项：submit 无审批、敏感动作无截图、可疑 URL、Policy deny
  • persist_evidence 默认自动分析（EVIDENCE_AUTO_ANALYZE）
  • API：/api/v1/evidence/analyze|analyze/persisted|analyze/jsonl
  • EventTypes：browser.evidence.analyzed / anomaly；单测全绿

修复判定

证据链从「只采集」升级为「采集 → 分析 → 事件告警」。 分析失败不阻断主链路；结果分级 info/warn/critical，可被 CRM/Hermes/告警订阅。
