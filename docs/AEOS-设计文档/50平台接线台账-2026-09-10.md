## 四、接线架构（怎么接，不是每个都手写）

项目已有**分层 worker 体系**，平台按优先级链挂到 worker 上：

| Worker tier | 是什么 | 支持 |
|---|---|---|
| `native_youtube` | YouTube OAuth 原生 | YouTube |
| `sau` | social-auto-upload | 抖音/快手/B站/TikTok/视频号 |
| `biliup` | biliup | 哔哩哔哩 |
| `xhs_mcp` | xiaohongshu-mcp | 小红书 |
| `aitoearn` | AiToEarn Relay | Facebook/Instagram/X/LinkedIn/YouTube/**Pinterest/Threads** |

**每平台一条 tier 链**（优先级），例：
```
抖音      → ("sau", "aitoearn")
小红书    → ("xhs_mcp", "sau", "aitoearn")
B站       → ("sau", "biliup", "aitoearn")
YouTube   → ("aitoearn",)          # 但 native_youtube 优先
默认      → ("sau", "aitoearn")
```

**所以"接一个平台" ≠ 写一个连接器**，而是：**① 在 `_PLATFORM_TIERS` 给它排一条 tier 链；② 确认链上的 worker 真支持它。**

## 五、一条线一条线串：建议顺序

按「**用户业务链的先后 + 接起来的价值**」排：

| 批 | 接哪些 | 为什么这个顺序 |
|---|---|---|
| **第 1 批** | **Reddit / WhatsApp / Pinterest / Threads** | ★ 你点名的 + `aitoearn` 已支持（改 tier 链即可，最快见效） |
| **第 2 批** | TikTok / 抖音 / 快手 / B站 / 视频号 | 走 `sau` / `biliup`，视频矩阵主力 |
| **第 3 批** | 小红书 / 百家号 / 微博 / 企鹅号 / 网易号 / 搜狐号 | 国内图文矩阵（文本适配器已在） |
| **第 4 批** | Telegram / LINE / Zalo / VK / Quora / Medium / Tumblr | 区域社媒 |
| **第 5 批** | Alibaba / Made-in-China / Global Sources / Amazon / eBay / Shopee / Lazada | B2B 电商（需要各自 API，工作量最大） |

**前三批接完（约 17 个平台），你的「多平台分发」就成型了。**

## 六、每接一个平台的检查清单

对一个平台，要确认**四件事**（缺一不可）：

| # | 检查项 | 对应代码 | 说明 |
|---|---|---|---|
| 1 | **能发** | `_PLATFORM_TIERS` + worker | 排 tier 链，确认 worker 真支持 |
| 2 | **能养号** | `social_nurture_service` + `platform_tenant_origins.nurture_rules` | 该平台的养号规则 |
| 3 | **有隔离环境** | `platform_tenant_origins.browser_profile_id` → `browser_profiles` | 指纹环境 |
| 4 | **有独立 IP** | `egress_endpoints`（assigned 槽位） | 静态 IP 分配 |

> **注意第 2/3/4 项**——这正是你补充的那一环。**光能发不够**：一个平台账号如果没有**独立的指纹环境和 IP**，多个账号会被平台判定关联而封号。**所以「接平台」= 发布 + 养号 + 隔离环境，三件一起接。**
