## 1. 目标态：获客莫比乌斯环（完整闭环）

```text
                    ┌─────────────────────────────────────────┐
                    │                 外层 DSH                 │
                    │  意图识别 · Skill 热插拔 · 权重/推荐      │
                    └───────────────────┬─────────────────────┘
                                        │ 携带 skill_version / exp_hints
                                        ▼
                    ┌─────────────────────────────────────────┐
                    │              内层爱马仕                   │
                    │  TaskGraph · 派发 · 审批 · 计费 · Trace  │
                    └───────────────────┬─────────────────────┘
                                        │ 执行
        ┌───────────────────────────────┼───────────────────────────────┐
        ▼                               ▼                               ▼
   获客触达                         内容/SEO/GEO                    建站/CRM/履约
  (WA/邮件/社媒)                   (DeerFlow/publish)              (site/PI/物流)
        │                               │                               │
        └───────────────────────────────┼───────────────────────────────┘
                                        │ 终态 + 业务结果
                                        ▼
                    ┌─────────────────────────────────────────┐
                    │           采集与证据层                    │
                    │  terminal_hook · Trace · Evidence        │
                    │  + 业务结果回写（询盘/成交/退信/回复）    │
                    └───────────────────┬─────────────────────┘
                                        ▼
                    ┌─────────────────────────────────────────┐
                    │           进化层 Evolution                │
                    │  EvolutionTaskRecord → ExperienceEntry   │
                    │  阈值晋升 raw→…→skill                    │
                    │  SkillVersion 草稿 → 离线评估            │
                    │  Canary 5/25/50/100 + 人审 → Production │
                    └───────────────────┬─────────────────────┘
                                        │ 版本化反哺
                    ┌───────────────────┴─────────────────────┐
                    ▼                                         ▼
         写回外层 DSH                                  写回内层爱马仕
   · skill 包版本/权重                             · L1 模板排序权重
   · persona/sop 偏好                             · 熔断阈值/on_fail
   · 场景推荐                                      · 预算与 wait_human 策略
                    │                                         │
                    └───────────────────┬─────────────────────┘
                                        ▼
                         下一轮执行更准 = 莫比乌斯同一面
```

**莫比乌斯定义（工程可验收）**：  
同一条业务面（获客/内容/履约）上，**执行结果必须改变下一次 DSH 选技能或爱马仕选模板/策略的可观察参数**，且该参数有版本、可回滚、有关联 Trace。

## 2. 断层诊断（为什么现在形不成环）

| # | 断点 | 现象 | 根因 |
|---|------|------|------|
| B1 | **双经验源不一致** | `hermes/experience_engine` 落本地 JSON；`evolution/ExperienceEntry` 落 PG | 两套统计，DSH/爱马仕不知信谁 |
| B2 | **成功经验提取弱** | 文档要求成功走 `extract_from_records` 批量提炼；失败有快路径，成功闭环不清 | terminal_hook 注释写明成功不在此建条目 |
| B3 | **业务结果未进经验特征** | 询盘是否成交、退信率、WA 已读——多数停在 CRM/邮件表 | 缺 `business_outcome` 回写钩子 |
| B4 | **skill 级经验不回到 Skill 包** | 晋升到 stage=skill 后，无自动/半自动生成 `SkillVersion(DRAFT)` 接到 `skills`/SKILL.md | Evolution「Skill优化」与 `registry/skill_service` 未焊死 |
| B5 | **DSH 不消费版本权重** | planner 只 `find_applicable` 塞 3 条 hint，不改模板优先级、不换 skill 版本 | 反哺停留在「提示」不是「策略」 |
| B6 | **爱马仕策略不进化** | 失败模式不降低该 executor 权重、不强制 wait_human | Governor 无经验策略表 |
| B7 | **Canary 与运行时路由脱节** | `canary.route()` 存在，但 Skill Router / 执行器选择是否走 canary 版本未全链保证 | 运行时 skill_version 未强制贯穿 TaskNode |
| B8 | **获客飞轮与 Hermes 环并行** | email DataFlywheel、flywheel_workflow、commercial_os 各自转 | 缺统一「场景经验」汇入 ExperienceEntry |
| B9 | **无闭环门禁指标** | selfcheck 不测「经验是否影响下次拆解」 | 缺 Mobius Gate 测试 |
| B10 | **空表/假成功污染经验** | mock 成功会「学会」错误模式 | 真实性门禁未进进化输入 |

## 3. 细部设计：补环（只焊线，不重建）

### 3.1 统一经验真源（消 B1）

| 项 | 规定 |
|----|------|
| **唯一业务真源** | PG `EvolutionTaskRecord` + `ExperienceEntry`（`evolution/`） |
| **Hermes ExperienceEngine** | 降级为**进程内轻量缓存/告警**，`record()` 同时 best-effort 调 `evolution` 入库；**禁止**只写本地 JSON 当唯一真相 |
| **读取接口** | DSH/爱马仕只读 `ExperienceStore.find_applicable` + `SkillVersion` 策略表 |

实现：`hermes/experience_engine.record()` 尾部增加 `EvolutionEngine.record_task_execution` 或 `terminal_hook` 同源写入（幂等键 `trace_id+node_id`）。

---

### 3.2 采集契约：终态 + 业务结果（消 B3/B10）

#### A. 执行终态（已有，补全字段）

所有 Hermes 节点 / DeerFlow bridge / 发布 / 邮件队列终态必须调：

```text
record_terminal_state(
  task_type, executor_id, success,
  tenant_id, duration_ms, tokens_used, cost,
  trace_id, skill_id, skill_version,
  input_summary, output_summary,
  metadata: {
    plan_id, node_id, scene_type,
    source: L1|L2|L3|L2_hybrid,
    degraded: bool,
    simulated: bool,          # 关键：假成功不得进「成功经验」
    channel: whatsapp|email|publish|...
  }
)
```

**规则**：`simulated=true` → 只入 `EvolutionTaskRecord`，**不得**提升 skill 经验置信度。

#### B. 业务结果回写（新建，细部）

| 业务事件 | 来源表/服务 | 写入 |
|----------|-------------|------|
| 询盘创建 | inquiries | `ExperienceBizOutcome(kind=inquiry_created, attributable_plan_id)` |
| 询盘→谈判/成交 | crm_pipeline / orders | `kind=deal_stage` stage=A..Won |
| 邮件退信/打开/回复 | email_tracking | `kind=email_engagement` |
| WA 已读/回复/封号风险 | whatsapp / engagement | `kind=wa_engagement` |
| 内容收录/GEO 提及 | seo / ai_visibility | `kind=seo_geo_signal` |
| 站点询盘转化 | site analytics | `kind=site_conversion` |

**归因模型（必须可算）**：

```text
plan_id / node_id / skill_version
  ← 由 TaskNode.metadata 与 outbound external_ref 带出
  ← CRM/inquiry 归因字段 attribution.plan_ref 回写（缺则补）

经验特征扩展（ExperienceEntry.pattern_data）：
{
  executor_id, capability,
  skill_id, skill_version,
  scene_type, industry_profile,
  success_ops: bool,          # 执行层成功
  success_biz: null|true|false,  # 业务层（7/30 天窗）
  metrics: { reply_rate, deal_rate, cost_per_lead }
}
```

进化评分：

```text
score = w1*ops_success + w2*biz_success + w3*efficiency - w4*risk
（无业务窗时只计 ops，标注 incomplete=true，禁止直接晋 skill 级）
```

### 3.3 成熟度与晋升（沿用旧阈值，补成功路径）

| stage | 晋升条件（在旧阈值上收紧） | 产出动作 |
|-------|---------------------------|----------|
| raw | 单次终态 | 入库 |
| validated | 同模式 ≥3 且非 simulated | 置信度更新 |
| pattern | ≥5 且 ops_success_rate≥阈值 | 生成「改进建议」结构化对象 |
| sop | ≥10 且（有 biz 则 biz 成功率≥阈值） | 写 `sop_ref` 草稿或更新 ECC 引用 |
| skill | ≥20 且 biz 窗完整 + 评估通过 | **强制** `SkillVersion(DRAFT)` + 评估任务 |

成功路径：Celery Beat 日更 `ExperienceStore.extract_from_records`（旧设计已有名）→ 与失败晋升共用 `promote_experience_stage`。

**改进建议对象（Pattern → 可执行）**：

```json
{
  "type": "template_reweight|skill_prompt_patch|governor_policy|persona_switch",
  "target": "L1:outreach_wa | skill:cold-email@1.0 | policy:wa_wait_human",
  "delta": {"weight": +0.15, "prefer_skill_version": "1.1.0-draft"},
  "evidence_ids": ["exp_...", "trace_..."],
  "proposed_by": "evolution.engine"
}
```

### 3.4 Skill 反哺 DSH（消 B4/B7）——外环焊点

```text
stage=skill 或 Pattern 建议 type=skill_prompt_patch
        ▼
EvolutionEngine.propose_skill_draft(experience_ids)
        ▼
SkillVersion(status=draft, skill_id, changelog, prompt_diff, test_set_ref)
        ▼
离线评估：固定金标集（每场景 ≥N 条）跑分，低于基线则拒绝
        ▼
publish_gate: draft→evaluation→canary(5%) [强制]
        ▼
DSH Skill Router 运行时：
  skill_version = CanaryRelease.route(tenant_id, skill_id)
  必须写入 TaskNode.skill_version 与 injected_assets
        ▼
效果验证（7/30 天）→ 人审 → production
        ▼
失败 → 回滚 version_control 状态机
```

**DSH 侧读策略（新函数，焊在 skill_pack_loader / router）**：

```python
def resolve_runtime_skill(skill_id, tenant_id) -> SkillRuntimeView:
    ver = canary.get_active_version(skill_id, tenant_id)  # canary or production
    weight = experience_store.skill_weight(skill_id, scene_type)
    return SkillRuntimeView(id, version=ver, weight=weight, body=load_body(ver))
```

禁止：Router 只读磁盘 `SKILL.md` 而忽略 SkillVersion。

### 3.5 爱马仕策略反哺（消 B5/B6）——内环焊点

#### A. L1 模板权重表（新表或 JSONB）

```text
HermesTemplatePolicy
  scene_type | template_id | weight | enabled
  min_success_rate | require_approval[] | budget_scale
  last_evolved_at | evidence_ids[]
```

- `decompose` L1：按 `weight * keyword_match` 排序，不再只看固定 `_TEMPLATES` 顺序  
- evolution `type=template_reweight` → 人审后 upsert weight（±步长上限，防震荡）

#### B. Governor 经验策略（熔断/加严）

```text
if ExperienceEntry[executor, scene].success_rate < X and count>=N:
    policy.require_approval += capability
    policy.budget_scale *= 0.8
if failure_pattern matches missing_env:
    route → mark executor degraded, on_fail=skip + 技能替换建议
```

写入 `GraphPolicies` 或节点级覆盖，**版本化**，可回滚。

#### C. payload 注入升级（在 J.4 上加强）

`_enrich_with_experience` 除 hints 外必须带：

```text
prefer_template_id, prefer_skill_versions[], avoid_executors[],
require_approval_hint[], confidence
```

L2 Prompt 与 Hybrid Compiler **必须消费**这些字段（测试断言）。

| 子飞轮 | 并入方式 |
|--------|----------|
| email DataFlywheel 五阶段 | 阶段结论 → `ExperienceBizOutcome(kind=email_engagement)` + 降低/提高 `outreach` 模板权重 |

### 3.7 莫比乌斯门禁（消 B9）——测试即设计

新增 `backend/tests/test_mobius_loop.py`（契约级，可 mock DB）：

| 用例 | 断言 |
|------|------|
| M1 | 模拟 N 次失败同一 executor → ExperienceEntry stage≥validated，且 TemplatePolicy/Governor 出现建议或策略变更 |
| M2 | `resolve_runtime_skill` 在 canary 租户返回 draft/canary 版本，TaskNode.skill_version 非空 |
| M3 | simulated 成功不增加 skill 置信度 |
| M4 | biz outcome 回写后 score 变化可反映到 find_applicable 排序 |
| M5 | 人审否决 canary → 不影响 production 权重 |
| M6 | DSH 拆解两次：第二次 `prefer_template/skill_version` 与第一次可不同（进化可观测） |

`orchestration_selfcheck` 增加项：

```text
- Experience 双写源一致（禁只写 JSON）
- 任意 production skill_version 可追溯 Experience/Canary

```

## 5. 运行时时序（获客一次完整莫比乌斯）

```text
1. 租户：「找沙特岩棉买家并发开发信」
2. DSH Intent → scene=lead_outreach
3. Skill Router：cold-email@canary(5%) 体重高于旧版
4. 爱马仕 Hybrid：outreach_wa 模板 + trade_ai + accio + engagement(wait_human)
5. 执行：抓线索 → 生成信 → 人审 → 邮件队列发送
6. terminal_hook：每节点 EvolutionTaskRecord + skill_version
7. 3 日后：open/reply/bounce → ExperienceBizOutcome
8. Evolution：同模式晋升；建议 template_reweight + skill DRAFT
9. Canary 灰度另一批租户
10. 人审通过 → production skill + TemplatePolicy.weight+
11. 下一次同类意图：DSH/爱马仕读到新权重与新 skill_version
12. 指标：第二次 CTR/回复率对比第一次 → 闭环证明
```

## 6. 与「万能皆可插」的关系

| 插座 | 进化后如何「更聪明」 |
|------|----------------------|
| DSH Skill 插座 | 版本+权重，按租户 canary 热更新 |
| Persona/SOP 插座 | 高分 persona/sop_ref 被模板优先引用 |
| 爱马仕航道插座 | 模板权重与审批策略随成功率调整 |
| 执行器插座 | 熔断/降级/换能力，而非无限重试 |
| 行业 Profile | 每行业独立经验桶，避免建材经验污染电子 |

**没有经验环的「万能皆可插」= 一次拼装；有莫比乌斯环 = 拼装结果改写下一次拼装。**

## 8. 禁止事项（防再断环）

1. 禁止 AI 直接改 production Skill/SOP（必须 Canary+人审）  
2. 禁止只写本地 JSON 经验当真源  
3. 禁止 mock 成功计入进化  
4. 禁止经验自动关闭 wait_human / 安全阀  
5. 禁止 n8n/邮件飞轮绕过 Evolution 私自「变聪明」  
6. 禁止无 evidence_ids 的权重修改  

---

## 9. 验收：什么叫「形成莫比乌斯环」

- [ ] 连续 2 周真实租户执行，ExperienceEntry 有 biz 字段非空样本  
- [ ] 至少 1 个 Skill 完成 draft→canary→production，且 TaskNode 带 version  
- [ ] 至少 1 条 L1 模板权重因证据被人审调整  
- [ ] `test_mobius_loop` 6 项 PASS  
- [ ] 管理端可见「进化提案」与回滚  
- [ ] 对外口径可说：**获客系统在闭环内越用越聪明**（有指标）  

---

## 10. 一句话

旧文档把 **进化六段、经验五级、灰度四步** 都写细了；缺的是 **业务结果回写 + skill/模板权重回写 DSH/爱马仕 + 统一真源 + 莫比乌斯门禁**。  
按本设计只焊这四根线，环就能从「零件陈列」变成「同一面循环」。
