## 3. 逐个判定详解

### ✅ #8 弹性微缩触觉反馈 —— 已落地

**判断**：做，且**做成 opt-in 类而非全局覆盖**。

**理由**：项目已有统一按压（导航 / 图标 `scale(0.97~0.98)`），扩展到内容区按钮是自然延伸。纯 CSS，零依赖。

**⚠️ 关键判断：为什么不全局覆盖 `.ant-btn`**
Ant Design Vue 的按钮自带 `transition` 与 `:active` / `loading` / `disabled` / `ghost` / `text` 多种变体。全局覆盖会与其打架（最典型的是 **loading 态图标位移**、disabled 态仍被缩放）。因此本层提供 `.uj-press` 系列类，并在类内**显式排除** `:disabled` / `[disabled]` / `.ant-btn-loading` / `[aria-disabled]`。

**技术要点**：用带过冲的 `cubic-bezier(.34, 1.56, .64, 1)` 做 **transition**（y 值 >1 天然过冲），而非 animation —— 无需 JS 即可实现"松手微冲过头再回弹"。

---

### ✅ #7 物理弹簧交错流 —— 已落地

**判断**：做（收益/成本比最高）。

**理由**：纯 CSS；项目已有 `nth-child` 递增 delay 先例；已有 reduced-motion 兜底可挂靠。

**⚠️ 两个必须处理的边界**：
1. **delay 必须截断**：本层实现为 `nth-child(1..12)` 递增 45ms，**第 13 项起统一 540ms**。否则 50 条列表的最后一项要等 2 秒才出现。
2. **分页/虚拟滚动要处理**：新加载的一页不应重放全部 delay，否则"加载更多"会视觉抖动。接入时需给新批次单独容器。

---

### 🟡 #6 动态弥散光晕边框 —— 已落地（安全子集）

**判断**：**部分做**。**原始描述里的"毛玻璃弥散光晕"在本项目不可用。**

**理由**：用户原描述是「背后映射出柔和的**毛玻璃**弥散光晕」，而 `backdrop-filter` 在本项目被**全局禁用**（`mint-glass-shell.scss:275-293`），原因是**送检水印会穿透半透明面板形成文字重影**。这不是风格偏好，是踩过的工程坑。

**改造方案**：
| 原描述 | 本项目实现 |
|--------|-----------|
| 旋转渐变描边 | ✅ 保留：`conic-gradient` + `@property --uj-aura-angle` + `mask` 抠 1px 环 |
| 毛玻璃背光 | ❌ **改为 `filter: blur(18px)` 的前景自模糊伪元素** —— 不采样背板，**不触发送检水印重影** |

**降级**：不支持 `@property` 的浏览器 → 退化为静态渐变环（`@supports not (...)`）。

**适用面约束**：**不超过 3 处**（AI 功能区 / 核心模块）。持续旋转动画长期占用合成层，铺开会掉帧。

---

### ⭐ #4 磁吸游标与滚动码表 —— 下一批优先做

**判断**：**最该做的一个**。地基已有，收益最高。

**理由**：
- 图表是看板核心，磁吸 + 码表**直接提升读数体验**
- echarts **自带** `axisPointer` 磁吸能力，只需定制（`snap: true` + `axisPointer.type: 'line'`）
- `useCountUp.ts` 已存在，`YdStatsCard` 已在使用
- **不需要新增依赖**

**⚠️ 两个技术要点**：
1. `axisPointer` 现仅 1 处定制（`admin/index.vue:481`）→ 需抽成通用配置
2. **`useCountUp` 需确认是否支持"从当前值补间"**。若实现是"从 0 重跑"，切换数据点时数字会跳回 0 再爬升 —— **这恰恰违背"码表丝滑翻滚"的诉求**。需先读该 composable 确认，再决定是否改造。

---

### 🟡 #1 3D 倾斜光影面板 —— 受限做

**判断**：**只做装饰性卡片，不做全站。**

**理由**（这是最关键的一条反向判断）：
- 本项目是**B2B 数据密集型后台**，主要交互对象是指标卡与表格。3D 倾斜会让**数字产生透视形变，直接干扰读数** —— 与落地页/作品集场景完全不同
- 需 `mousemove` 持续监听 → 与图表 tooltip、表格悬停高亮争抢
- 触屏上"手指按压面板"时**手指会遮挡内容本身**

**落地条件（缺一不可）**：
- 仅 `@media (hover: hover) and (pointer: fine)` 启用（触屏/粗指针直接不加载）
- 倾斜幅度 **≤ 4°**（超过会明显形变）
- 最多 **3 处**装饰卡（如工作台 hero 卡、空态插画卡）
- 必须接 reduced-motion

---

### 🟡 #3 共享元素无缝展开 —— POC，仅 1 条链路

**判断**：**用 View Transitions API 做渐进增强，不自研 FLIP。**

**理由与障碍**：
- **最大障碍**：`layout/index.vue:73` 的 `router-view` 只包 `keep-alive`，**没有 `<Transition>`**。加转场会与 `keep-alive` 的缓存语义冲突（缓存页被复用时不触发 enter 钩子），**需先实测兼容性**
- 自研 FLIP 改动面大（列表项 + 详情页 + 路由三方联动），且项目**无任何动画库**
- Vue 生态没有现成的 shared-element 方案（framer-motion 是 React 的）

**方案**：`document.startViewTransition()` 是**渐进增强** —— 支持（Chrome 111+）则有转场，不支持直接跳转，**零回归风险**。

**范围**：本期**只做 1 条链路 POC**（建议：租户列表 → 租户详情），验证 keep-alive 兼容后再决定是否铺开。

---

### 🟡 #5 阻尼弹性抽屉 —— 分两步

**判断**：**缓动立刻做；Bottom Sheet 需求待确认。**

**理由**：
- 项目**没有底部导航**（<768px 时侧栏是抽屉，`YdProSidebar.vue:155`），说明当前形态是**侧抽屉**而非底部抽屉
- "阻尼橡皮筋 + 速度吸附"需要**新建 Bottom Sheet 组件**（含手势处理）。项目有 `useFloatingDrag.ts` 可复用，但仍需开发与测试
- **低垂果实**：现有 `a-drawer`（13+ 文件在用）可直接换弹性缓动曲线 —— 已找到先例：`login-slide-trae.css:62,103` 已在用 `cubic-bezier(0.68, -0.55, 0.265, 1.55)`

**步骤**：
1. **先**：给 `a-drawer` 统一换弹性缓动（低成本、立刻见效、无新组件）
2. **后**：若移动端确有"底部弹层"场景（如移动端筛选面板），再做 Bottom Sheet

---

### ❌ #2 流体胶囊形变 —— 建议不做

**判断**：**本期不做。**

**理由**（成本/收益比最差）：
1. 需要 **FLIP / `clip-path` morph / 自定义 layout animation**，项目**零基建**
2. Vue 生态**没有成熟的"胶囊→面板"morph 库**可用（framer-motion 是 React 专属）
3. 项目弹窗体系是 Ant Design Vue 的 `Modal` / `Drawer`，改造需**覆写其生命周期与整个动画管线** → 会破坏既有弹窗的一致性（13+ 处 `a-drawer`、大量 `a-modal` 都在依赖现有行为）
4. **静态排版 → 弹窗**的形变，收益主要在"炫技观感"，对 B2B 后台的**任务完成效率无实质提升**

**替代方案（低成本、保留 80% 观感）**：
- 给现有 `Modal` / `Drawer` 换**高阻尼弹性缓动曲线**（与 #5 共用一套曲线令牌）
- 触发按钮加 `.uj-press` 微缩反馈，形成"按下→弹出"的动作连贯感
- 成本：改几个 CSS 变量；收益：接近的连贯感，零风险

## 9. 批次 B1 已执行：#4 磁吸游标与滚动码表（2026-09-20）

### 9.1 先验证了那个关键假设 —— 结论：**缺陷真实存在**

动手前按要求先读 `src/composables/useCountUp.ts`，第 44 行：

```ts
const val = to * easeOutCubic(t);   // ← 恒从 0 插值到 to
```

**无论当前显示什么值，每次更新都从 0 重跑。** 图表游标一滑动，数字就会反复跳回 0 再爬升 —— 与「机械码表丝滑翻滚」的诉求正好相反。

**调用面实测**：全仓仅 **1 个调用方** —— `components/youding/YdStatsCard.vue:48`（指标卡本身）。爆炸半径可控。

## 11. 批次 B2：抽屉统一缓动（2026-09-20，已执行）

### 11.1 为什么只能走 CSS 覆盖（机制实测）

| 事实 | 出处 |
|------|------|
| 位移层基类写死 `transition: all ${motionDurationSlow}` | `ant-design-vue/es/drawer/style/index.js:65` |
| `-enter-active` / `-leave-active` 上又重复设置一次 | `ant-design-vue/es/drawer/style/motion.js:12` |
| 两处缓动都是 CSS 关键字 `ease`，**没有对应 theme token** | token 只能改时长 `motionDurationSlow`，改不了曲线 |
| 选择器**不带 hashId**（`genComponentStyleHook('Drawer', …)` 未传） | drawer `style/index.js` 尾部 |

⇒ 结论：覆盖是唯一路径，因此本段**做不到 opt-in**（是全层唯一的全局覆盖，已在文件头注明）。

### 11.2 ★ 为何**否决**过冲曲线（这条最容易被做错）

原需求写的是「弹性缓动」，直觉会直接上 `cubic-bezier(.34,1.56,.64,1)`。**这是错的，原因是几何必然：**

抽屉**贴边锚定**。以右侧抽屉为例：静止位 `translateX(0)` 时，面板右边缘与视口右边缘**重合**；过冲会让 `translateX` 变成**负值** → 面板整体左移 → 右侧**露出遮罩缝隙**。左/上/下同理，各自在锚定边露缝。**与曲线参数无关，只要过冲就必然露。**

**实测证据**（`docs/抽屉缓动验证-B2-2026-09-20.html`，三条泳道同结构同宽同时开）：

| 泳道 | 曲线 | 实测最大缝隙 |
|------|------|------------|
| AntD 原生 | `ease` 300ms | **0.0px（未越界）** |
| **B2 采纳** | `expo-out` / `expo-in` | **0.0px（未越界）** |
| 过冲曲线（否决） | `back-out` 340ms | **最大 23.5px** ← 露缝 |

交叉验算：面板实际宽 **240.0px**，理论过冲 9.8% × 240.0 = **23.5px**，实测 **23.5px**，**偏差 0.0px**。

⇒ 真正需要「弹性回弹」的是 **#5 阻尼 Bottom Sheet**：那是**手势驱动**的（松手按速度定吸附锚点），不在本批次。

### 11.3 采纳方案

| 阶段 | 曲线 | 时长 | 理由 |
|------|------|------|------|
| 进入 | `cubic-bezier(0.16, 1, 0.3, 1)`（expo-out） | **340ms** | 起步快、收尾极慢 → 有重量、顺滑；y 值恒 ≤ 1（过冲 = 0） |
| 退出 | `cubic-bezier(0.7, 0, 0.84, 0)`（expo-in） | **200ms** | 「退出快于进入」是通行 UX 惯例 |

即「**用减速而非越界**」实现原需求里想要的手感。遮罩层同步同一组曲线与时长，避免「面板已到位、遮罩还在淡入」的割裂感。

4 个 CSS 变量做**单点开关**，改回 `ease` / `300ms` 即完全复原原生手感：
`--uj-drawer-enter-ease` / `--uj-drawer-enter-duration` / `--uj-drawer-leave-ease` / `--uj-drawer-leave-duration`

### 11.4 选择器为何必须加 `html` 前缀（三个坑点）

1. 抽屉默认 portal 到 `body` —— **`.shell` / `.yd-page` 这类祖先选择器全部落空**（本项目既有玻璃/暗色样式都挂在 `.shell` 下，本层不能照抄）；
2. AntD 样式由 cssinjs **运行时注入**，位置在静态样式之后 → 同权重（0,2,0）时**靠后者取胜**；
3. 加一个元素选择器 → 本层 (0,2,1) 稳压 AntD (0,2,0)，**全程无需 `!important`**（仅 `prefers-reduced-motion` 降级块用 `!important`）。

另外补了两处防御：
- 落位首帧 `transition: none`（`-enter-start` / `-appear-start`），否则会从上一个位置滑进来；
- `will-change: transform` **只在 `-enter-active` / `-leave-active` 期间打开**，类名一撤即释放 → 不让 14 个抽屉长期占合成层。

### 12.2 接线（`vue-echarts` 实例获取路径是实测确认的）

```ts
const trendChartRef = ref<unknown>(null);          // 模板 ref
const { activeIndex, activeValue, bindWhenReady } = useChartCursor<number>((info) => {
  const v = trendData.value[info.dataIndex];
```

**★ 关键：`<v-chart ref="r">` 上 `r.chart` 才是 ECharts 实例，`r` 本身不是。**

直接 `bind(r)` 会因 `r.on` 不存在而**静默失败**（新增 `resolveChart()` 专门处理这个解包）。

**为什么要 `bindWhenReady`（有界重试，最多 30 帧）**：图表被 `v-if="trendEmpty"` 的骨架屏包着，父组件 `onMounted` 时 ref 还是 `null`；且 vue-echarts 的实例初始化走 `initDeferred` + `nextTick`，比 ref 赋值再晚一帧。**超限即放弃返回 false，不无限自旋。**
