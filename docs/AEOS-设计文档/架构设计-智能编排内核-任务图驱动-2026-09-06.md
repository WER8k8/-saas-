# 智能编排内核设计：任务图驱动（Plan-as-Data）

> 版本 V1.0 ｜ 2026-09-06 ｜ 状态：待评审
> 目标：让 `DeepSeek Harness + Accio Work + n8n ↔ Hermes ↔ ECC ↔ DeerFlow` 成为**可随意组合、可智能发挥**的一套内核，而不是一条写死的管道。验收标准：客户提出要求 → 智能编排 → 结果顺利返回，且**任何一段都能被替换/跳过/换路，不改代码**。

---

## 0. 一页纸结论（给决策者）

1. **链路组合"随意打乱"的唯一实现方式：Hermes 的输出是一张任务图（JSON 数据），不是代码调用。** 执行器照图干活。换组合 = 换图，零代码改动。
2. **DeepSeek Harness 不做租户和沟通。** 它是 Hermes 大脑里的"推理线束"：把 DeepSeek 包起来，强制结构化输出任务图、只准调注册过的工具、超预算即停。租户/沟通留在已有的 BFF 网关层（稳的活和聪明的活分开）。
3. **聪明程度 = 三件事**：Planner 用什么模型（Harness 接的 DeepSeek/GLM 可切换）× 喂什么上下文（ECC 的 SOP + 租户记忆 + 历史失败经验）× 有没有反馈闭环（失败证据回流，下次不再犯）。
4. **智能化分四级爬坡**：L0 写死 → L1 图模板 → L2 大模型动态出图 → L3 执行中重规划 → L4 经验自优化。每级都可独立上线收钱。
5. 现有资产（TaskControl 账本/幂等键/影子双写、Browser Runtime 取证、n8n 路由、ECC 8 专家）**全部复用**，缺的只是三份契约和执行监督器。

## 1. 现状诊断（为什么现在"打乱"不了）

| 组件 | 现状 | 差距 |
|---|---|---|
| n8n | Docker 在跑（5678），有 routes/n8n.py | 只有"被调"，没有作为触发源/分发出口的标准化契约 |
| Hermes | services/hermes/ 15+ 模块（agency 专家桥、意图路由、brand_guard…） | 输出不是标准化任务图；触发入口未收敛 |
| ECC | 8 专家面板 + inspection registry | SOP 是"面板"，不是"按 capability 可检索注入的知识服务" |
| DeerFlow | 容器 + deerflow_job_service + 影子双写（30/30） | 作为执行器没有统一契约（input/output schema） |
| Accio | models/ubrain_accio.py + ubrain.py | 技能注册机制只服务 Accio 自己，未开放为通用工具注册表 |
| TaskControl | ai_tasks 账本 + 幂等键 + 双记账互斥闸 | 能记任务，但不能"按图调度"（无节点依赖编排） |
| DeepSeek Harness | 散在 consistency_harness_service 等处 | 未抽成独立"Planner 线束"组件 |

结论：**零件齐全，缺三份契约 + 一个执行监督器。** 不需要重写任何现有模块。

## 2. 三份核心契约（整个设计的关键）

### 契约一：IntentEvent（统一意图事件）——"所有入口说同一种话"

n8n webhook、网页对话、Paperclip 心跳、定时任务、开放 API……**全部翻译成同一种事件**再进 Hermes：

```json
{
  "event_id": "evt_7f3a...",
  "tenant_id": "d2d18d4d...",
  "channel": "n8n | web | api | heartbeat | schedule",
  "intent": "generate_site | find_leads | write_article | deep_research | publish_content | custom",
  "payload": { "...intent 的业务参数，如产品图 URL 列表..." },
  "context": {
    "user_role": "tenant_admin",
    "language": "zh",
    "quota_gate": true,
    "budget_hint": "standard"
  },
  "reply_to": { "channel": "n8n", "webhook": "https://n8n:5678/webhook/xxx" }
}
```

要点：`reply_to` 让"结果怎么送回客户"也变成数据——n8n 触发的就回 n8n，网页聊天的就走会话流，邮件来的就回邮件。

### 契约二：TaskGraph（任务图）——Hermes 的输出，全系统的通用货币

```json
{
  "plan_id": "plan_9c21...",
  "event_id": "evt_7f3a...",
  "strategy": "deep | fast | cheap",
  "nodes": [
    {
      "id": "n1",
      "executor": "files",            // 执行器：deerflow | accio | ai_engine | browser | n8n | files | hermes(内置)
      "capability": "media.upload",   // 能力名（执行器注册表里声明过）
      "input": { "..." : "..." },
      "sop_ref": "ecc://site-building/checklist-v5",   // ECC 知识注入点
      "model_hint": "glm",            // 该步用什么档位的模型（可选）
      "depends_on": [],
      "retry": { "max": 2, "backoff": "exp" },
      "budget": { "max_tokens": 50000, "max_seconds": 600 },
      "on_fail": "abort | skip | degrade:<fallback_node>"
    },
    { "id": "n2", "executor": "ai_engine", "capability": "site.generate",
      "depends_on": ["n1"], "input_from": { "product_images": "n1.output.urls" },
      "sop_ref": "ecc://site-building/brand-voice-v2" },
    { "id": "n3", "executor": "browser", "capability": "site.evidence", "depends_on": ["n2"] },
    { "id": "n4", "executor": "n8n", "capability": "dispatch.notify", "depends_on": ["n3"],
      "input_from": { "preview_screenshot": "n3.output.image" } }
  ],
  "policies": {
    "max_parallel": 3,
    "budget_cap": { "max_tokens_total": 200000 },
    "approval_required": ["publish.*", "email.send"],   // 命中即挂起等人审（复用 approval_gate）
    "degradation": "n2 失败 → 切换模板生成降级节点 n2f"
  }
}
```

要点：
- **依赖边让并行成为常态**：无依赖的节点自动并行（受 max_parallel 约束）。
- **`on_fail` + `degradation` 让"打乱组合"包括失败路径**：DeerFlow 超时？图里预置降级节点（如模板生成）。
- **`sop_ref` 让 ECC 成为"随时可插的知识插座"**：任何一个节点都能挂一份 SOP，ECC 从"面板"升级为"知识服务"。
- **`approval_required` 复用已有 approval_gate**：发布类/发信类节点自动等人审——骨架已有此语义。

### 契约三：Executor Contract（执行器契约）——任何能力都可插拔

每个执行器向**注册中心**声明（注册表存 DB，租户/平台两级，复用 tenant_ai_config 的模式）：

```
executor: deerflow
capabilities:
  - research.deep_run   { input: {topic, depth}, output: {report, citations}, avg_cost: 0.4 crédit, timeout: 900s, health: /health }
  - video.render        { ... }
```

执行器只需实现一个入口：`run(node, context) -> node_result`，以及健康检查。**DeerFlow、Accio、ai_engine、Browser Runtime、n8n（作为外部 SaaS 动作的执行器）、甚至未来的第三方 MCP 工具，全部平等注册。** 这就是"能效随意发挥"的物理基础——加能力 = 注册一行，不动内核。

## 3. 组件职责终版（回答"Harness 做外层？"）

| 组件 | 职责 | 明确不做 |
|---|---|---|
| **租户网关（已有 BFF）** | 身份/租户上下文/多渠道接入/流式回传/限流 | ❌ 不做任务拆解 |
| **Hermes（调度中枢）** | ①IntentEvent 归一化 ②路由给 Harness 出图 ③把图交执行监督器 ④结果按 reply_to 回传 ⑤反馈闭环归档 | ❌ 不自己跑长任务 |
| **DeepSeek Harness（Planner 线束）** | 装配上下文（租户+记忆+ECC SOP）→ DeepSeek 推理循环 → 强制输出 TaskGraph JSON（schema 校验，失败重试/降级到模板图） | ❌ 不做租户/沟通/执行 |
| **ECC（知识服务）** | 按 `sop_ref`/capability 检索 SOP 片段注入节点；提供质检标准（inspection）与专家人设 | ❌ 不执行 |
| **TaskControl（执行监督器+账本）** | 图落库（节点=ai_tasks，幂等键 `plan_id:node_id`）、状态机推进、并行调度、重试/降级执行、配额/预算闸 | ❌ 不理解业务语义 |
| **执行器**（DeerFlow/Accio/ai_engine/Browser/n8n） | 只做一件事：按契约跑完一个节点，返回结构化结果 | ❌ 不互相直接调用（一切经图） |
| **n8n（双角色）** | 入口：webhook → IntentEvent 适配器；出口：dispatch.* 能力的执行器 | ❌ 不承担调度 |

**为什么 Harness 不做外层**：租户沟通层要的是 100% 稳定（鉴权、隔离、限流、多语言流式），大脑要的是 100% 灵活（随时换模型换策略）。两者耦合的结果是每次改策略都要动鉴权代码——这是把最稳的和最善变的焊死在一起。你们已有 tenant_middleware/BFF，直接复用。

## 4. 智能化四级爬坡（"能效随意发挥"的阶梯）

| 级别 | 行为 | 技术形态 | 商业价值 |
|---|---|---|---|
| **L0 静态管道**（现状） | 代码写死调用链 | 现有各 service 直调 | 能跑但不能组合 |
| **L1 图模板** | intent → 预定义图（建站图/获客图/研报图…），参数替换 | 图模板库（存 DB，可运营配置） | **第一步可卖**：组合可配，运营可调 |
| **L2 动态出图** | Harness 让 DeepSeek 按意图+可用能力实时生成图 | Planner 线束 + schema 校验 + 工具白名单 | "随意组合"真正成立；聪明程度=模型×上下文 |
| **L3 执行中重规划** | 节点失败/中途新信息 → Harness 重出剩余子图 | 监督器回调 Harness，replace 剩余节点 | 韧性：自动换路、降级、省预算 |
| **L4 经验自优化** | 失败证据/成本/时长回流 → 影响下次出图偏好 | ExperienceEntry 已有，接 Planner 上下文 | 越用越聪明，形成数据壁垒 |

**建议节奏：L1 上线收钱 → L2 打通"随意组合" → L3/L4 建壁垒。** L1 与 L2 的区别只是图从哪来（人配 vs 模型生成），执行监督器完全同一套——所以先建内核不会白做。

## 5. 状态机与可靠性（骨架能承重的保证）

**节点**：`pending → ready → running → succeeded | failed | skipped | degraded`
**图**：`planning → (approval 挂起，若命中 approval_required) → executing → completed | partial | failed | aborted`

- **断点恢复**：图与节点状态全部落 ai_tasks（幂等键已有），后端崩溃重启后监督器扫 unfinished 图续跑（复用心跳引擎的补偿思路）。
- **预算三闸**：节点级（budget）→ 图级（budget_cap）→ 租户级（plan_gate/quota）。任一爆掉即熔断并按 on_fail 走降级。
- **双记账互斥**：沿用现有约束——`TASK_CONTROL_ENABLED` 与 token_ledger 聚合路径二选一，切换前 PG 真冒烟（轮16-22 交接的红线）。
- **取证**：publish/dispatch 类节点终态后旁路 Browser Runtime 截图（已有挂点），证据 id 写回节点 result。

## 6. 组合矩阵示例（"随意打乱"的真实形态）

| 客户说 | 触发 | Hermes 出的图 |
|---|---|---|
| "用这些产品图帮我建官网" | n8n/网页 | `files.upload → products.link → ai_engine.site_generate → i18n.translate → geo.llms → browser.evidence → n8n.notify(预览截图)` |
| "找 50 个德国保温材料买家并开发信" | 网页 | `accio.lead_search → accio.enrich → ai_engine.write(挂 ECC 开发信 SOP) → brand_guard.check → [人审] → n8n.email_send → tracking` |
| "深度调研东南亚市场出报告" | API | `deerflow.research → ai_engine.report → n8n.pdf_deliver` |
| "竞品降价了，跟进一下" | 网页 | Hermes 判定简单 → **直答，不出图**（省钱路径） |
| 心跳例行任务（每周 GEO 检查） | heartbeat | 图模板 L1 直接实例化，全程无人审 |
| DeerFlow 挂了 | — | 图里 `on_fail: degrade:n2f` 自动切 ai_engine 快路径，客户无感 |

同一内核，路径千变万化——**这就是"链路可以打乱"的工程含义。**

## 7. 落地路线（复用现有资产，四阶段）

| 阶段 | 内容 | 交付判据 | 依赖 |
|---|---|---|---|
| **P1 内核**（~1.5周） | 三契约 schema 定义 + 图落 ai_tasks（节点表扩展 plan_id/node_id/depends_on）+ 执行监督器（并行/重试/on_fail）+ Hermes 出 L1 图模板 | "客户上传产品图→建站→取证→n8n 通知"全链在图上跑通，断点可恢复 | TaskControl 开关灰度红线（PG 冒烟） |
| **P2 执行器收编**（~1周） | Executor 注册中心 + DeerFlow/Accio/Browser/ai_engine 按契约改造（现有桥接代码直接包一层）+ n8n 双向适配器 | 任意执行器拔掉，图自动降级到备用执行器 | P1 |
| **P3 Harness 独立**（~1周） | DeepSeek 线束抽独立组件（工具注册表开放给全部 capability，不只 Accio）+ ECC SOP 检索服务化 + schema 校验/降级模板图 | L2：给一个没见过的意图，Harness 能出一张合法可跑的图 | P2 |
| **P4 智能爬坡**（~2周） | L3 重规划 + L4 经验回流 + 组合矩阵回归测试集（含故障注入） | 故障注入测试：杀 DeerFlow 容器，图自动换路完成交付 | P3 |

**P1 期间顺手修**（前面实测发现、属于本链路的断点）：site_builder/product_images/sitemap 三处路由未挂载、`/site-ai/publish` 假发布、建站不自动带产品库图片。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| LLM 出的图不合法/瞎编 capability | schema 强校验 + capability 白名单 + 失败回退 L1 模板图（绝不用假图硬跑） |
| 图爆炸（节点过多）成本失控 | 图级预算闸 + 节点数上限 + 简单意图禁止出图（直答） |
| 双记账冲突 | 沿用互斥闸，P1 起步就只走一条路径 |
| PG 上影子双写未验证（轮16-22 遗留） | P1 期间在 PG 真库跑图执行冒烟，作为开关灰度前置条件 |
| n8n 侧客户自建流程失控 | n8n 仅作触发/出口适配，编排权始终在 Hermes；n8n 侧只留薄 webhook |

## 9. 验收清单（这套设计做没做成的判据）

- [ ] 同一意图，从 n8n 触发和从网页触发，产出与回传一致
- [ ] 拔掉 DeerFlow 容器，深研报任务自动降级完成交付
- [ ] 新增一个执行器能力，只写注册声明 + run()，内核零改动
- [ ] 任意节点失败，图状态与取证证据可完整回放
- [ ] 简单意图不产生任何图执行成本
- [ ] 租户 A 的图、预算、记忆与租户 B 零互通
