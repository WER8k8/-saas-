## 三、后端模块层级与依赖（父子树）

```
backend/app/                         (根包)
├─ main.py                           入口：装配 APIRouter(prefix=/api) + 中间件 + 生命周期
├─ api/  (146 路由模块, v1/routes/*)  HTTP 边界；auto_register 扫描挂载
│   └─ v1/routes/{auth,agent_hub,content,finance,...}  被依赖：main→api_router→routes
├─ core/                             配置/安全/鉴权基类（被全栈依赖）
├─ db/                               引擎/会话/迁移（被 models/services 依赖）
├─ models/                          238 ORM 模型（被 services/schemas 依赖）
├─ schemas/                         701 Pydantic（API↔模型 契约）
├─ repositories/                    数据访问层（被 services 依赖）
├─ services/  (41 子包)             业务中枢
│   ├─ hermes/        编排（调度 others）
│   ├─ deerflow/      研报内容
│   ├─ goodjob/       CRM 桥（未真接）
│   ├─ adapters/      TradeAI/GoodJob 适配（桩）
│   ├─ billing/       计费（SaaS+Token+槽位）
│   ├─ model_gateway/ 模型网关（被 ai/* 依赖）
│   ├─ browser_runtime/ 取证（被 egress 依赖）
│   ├─ n8n/           出站（被 egress 依赖）
│   ├─ seo/ geo/ media/ crawlers/ ... 领域服务
│   └─ vault/ facade/ 摆设组件（前审 2 个）
├─ tasks/  (32 Celery)              异步（被 services 触发，依赖 Redis/Celery）
├─ workers/                         worker 启动
├─ domains/ orchestration/ performance/ geo_engine/ graduation/ data/ 横切
```

**依赖方向（关键边）**：
- `main.py` → `api` → `services` → `repositories` → `models`/`db`
- `services/hermes` → 各 executor → `services/{deerflow,goodjob,adapters}` / `tasks` / `model_gateway`
- `services/egress` → `browser_runtime` + `n8n`
- `model_gateway` ← `services/ai/*`, `deerflow`, `hermes`
- 顶层 import 热点：`app`(5,867)、`sqlalchemy`(1,139)、`fastapi`(478)（见百维 D 段）
