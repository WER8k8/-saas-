## 6. 主链路端到端场景（用户点名的核心线，P0）

### 链路 A：AI 写新闻 → 审核 → 官网展示

| # | 场景 | 步骤 | 看什么 / 通过标准 |
|---|---|---|---|
| A-1 | AI 生成文章 | 租户在 AI 中心选"文章生成"，输入主题+关键词，点生成 | 返回结构完整（标题/摘要/正文/标签）；`ai_usage`/`token_ledger` 有本次计量记录 |
| A-2 | 网关故障降级 ⚙️ | 临时把 AI 网关地址改错，再生成 | 返回**明确报错或降级文案**，绝不能把占位符当真文章静默交付（对齐 `no_fake_delivery` 原则） |
| A-3 | 草稿→发布流转 | 生成后先存草稿，再改 `is_published=true` | 官网列表**只出现已发布**的；草稿匿名不可见 |
| A-4 | slug 唯一性 | 用相同标题生成两篇 | 第二篇 slug 自动去重，详情页互不串 |
| A-5 | 富文本安全 | 正文里塞 `<script>alert(1)</script>` | 官网渲染时被转义/过滤，不执行 |
| A-6 | SEO 字段落库 | 创建时填 `meta_title/meta_description/tags` | 详情页 HTML 源码里 `<title>`、`description`、`og:*` 与所填一致 |
| A-7 | 计量正确性 | 生成前后查 token_ledger | 扣减次数/数额与调用次数一致，无双扣（D1/D2 修复的回归点） |

### 链路 B：文章 → 视频

| # | 场景 | 步骤 | 通过标准 |
|---|---|---|---|
| B-1 | 文章转视频（mock） | 贴入文章，`auto_render=false` 创建→手动 run | 分镜脚本是**真 LLM 生成**（非模板拼接）；任务 queued→done；mp4 200 |
| B-2 | 真实渲染 ⚙️ | 配好 Cosmos 端点后重跑 B-1 | mp4 时长/分辨率符合请求参数；失败时 `error_message` 给出可操作提示（对齐 D 系列体验） |
| B-3 | 渲染队列并发 | 同时提交 3 个视频任务 | 队列不丢任务、不互相覆盖；`/render-queue` 状态与实际一致 |
| B-4 | 任务权限边界 | tenant A 的 token 去读 tenant B 的 task id | 403/404，绝不返回对方数据（**隔离红线**） |
| B-5 | 媒体保留与清理 ⚙️ | 把 `MEDIA_RETENTION_HOURS` 调最小，等清理调度跑 | 过期文件被清、`file_purged` 标记正确、列表不再展示死链 |
| B-6 | SEO bundle | 调 `GET /tasks/{id}/seo-bundle` | 返回视频标题/描述/缩略图等 SEO 元数据，`seo_ready` 状态正确 |
| B-7 | 发布到站点 | 调 `POST /tasks/{id}/publish-to-site` | 官网/租户页出现该视频，公开接口 `/public/tenants/{domain}/videos` 可见 |

### 链路 C：智能编排调度（骨架核心，默认开关全关，需专门开一轮）⚙️

| # | 场景 | 步骤 | 通过标准 |
|---|---|---|---|
| C-1 | 开关切换安全 | 开 `TASK_CONTROL_ENABLED` 前后各跑一遍视频链路 | 计量**不双扣**（config 注释明确与 token_ledger 互斥）；切换期无半执行状态 |
| C-2 | Goal→Task 派生 | 用 orchestrator 创建目标（如"本周发 3 篇内容"） | goal_chain 正确派生子任务，状态机 queued→executing→done 全程可查 |
| C-3 | 心跳引擎自动派发 | 开 heartbeat，投放一批任务 | 自动认领/执行/回收；心跳中断后任务不丢（有补偿） |
| C-4 | 审批闸门 | 配置需要人工审批的任务类型 | 任务停在 awaiting_approval，审批后继续，拒绝后终止且留痕 |
| C-5 | 预算护栏 | 把 budget_guard 阈值调到极低再触发生成 | 超预算被拦截并有明确报错，不产生半成品 |
| C-6 | Paperclip 影子双写 | 开 TASK_CONTROL 后创建/执行/完成一个 Paperclip 任务 | ai_tasks 表出现幂等键 `paperclip:{task_id}` 的影子记录，成功/失败状态对齐 |
| C-7 | DeerFlow 去重 | 让 Paperclip 代执行一个 DeerFlow job | 不产生重复影子（`on_job_enqueued` 跳过逻辑生效） |
| C-8 | 浏览器取证旁路 ⚙️ | 开 `BROWSER_RUNTIME_ENABLED`，跑 publish 类 intent | 终态后生成截图 EvidenceRecord；Playwright 未装时降级 noop 不报错 |
| C-9 | 编排崩溃恢复 | 任务执行中强杀后端进程，重启 | 任务状态可恢复/标记失败，不出现永久 running 僵尸 |

## 13. 混合驱动：两条延长链路实测（DeepSeek 外层 + Accio + n8n → … → trade-ai-agent / goodjob-crm）

### 13.1 两条链路的真实形态（代码核实）

```
【链路 A】… → n8n(分发) → trade-ai-agent（营销自动化：社媒触达/智能回复/跟进）
【链路 B】… → n8n(分发) → goodjob-crm（外贸 CRM：客户池/单证/任务执行）
```

**下游接入机制（两系统不同）**：

| 下游 | 通道 | 机制 | 状态 |
|---|---|---|---|
| goodjob-crm | **任务包通道**（EXECUTOR 六插槽契约） | UJ `app/orchestration/executors/goodjob_executor.py` → HTTP POST `GoodJob:4188/api/uj-bridge/task-packages`；五字段信封（tenant_id/idempotency_key/lease_ttl/checkpoint/budget）+ Bearer `GOODJOB_BRIDGE_TOKEN`↔`UJ_BRIDGE_TOKEN` 双闸 + zod 校验；D3 红线：只吃 UJ 签发的包，调度主权在 Hermes | ✅ 实测通 |
| trade-ai-agent | **身份通道**（annex 统一登录）+ 代码移植 | UJ `POST /api/v1/annex/ticket {annex:"trade-ai"}` 签 5 分钟一次性 JWT（aud=annex:trade-ai）→ 附属侧 `/annex/redeem` 换身份映射；附属本地登录闸门化停用（ANNEX_LOCAL_LOGIN_ENABLED），身份唯一来源=UJ；另有 execution_context.py 等代码级移植（MIT） | ✅ 签发实测通 |
| DeepSeek Harness | **模型外层** | `AI_DEEPSEEK_*` → ai_engine `_init_deepseek_llm` 注册为 cost_optimized 兜底模型（主网关 503 时接手） | ⚠️ 未激活（D15） |

### 13.2 混合驱动标准剧本（怎么"混"）

```
① n8n 触发（webhook → /api/v1/n8n/webhook/{id} → EventBus）        [D8 修复后可用]
② Hermes 调度（plugins/{id}/run → orchestrator → intent 路由）
③ ECC 约束（宪法只读边界 + 8 专家 SOP；patrol 巡检持续监控）
④ DeerFlow 深度执行（job 状态机 + checkpoint + 租户配额 budget_guard）
⑤ 产物分叉：
   ├─ 内容类 → content_masters / news（官网 SEO/GEO）
   ├─ 销售类 → Accio 开发信（needs_confirmation 人工确认后）
   └─ 客户/单证类 → GoodJobExecutor.submit(task_type=customer_pool.sync / trade_document.generate)
⑥ n8n 自动化分发 → trade-ai-agent（annex 票据登录后调其 80+ 路由做社媒触达/跟进）
⑦ 用户接收结果（管理端看板 + 通知 + 审计留痕）
DeepSeek 外层横切：任一环节调 LLM 时作为 cost_optimized 兜底（qwen 503 时顶上）
```

**混合的关键规则（代码里写死的铁律）**：
- GoodJob 只吃 UJ 签发的任务包，**永不反向调度**（D3 红线，桥注释明文）
- 附属系统身份唯一来源 = UJ annex 票据，本地登录停用
- 开发信发出前必须过 `needs_confirmation` 人工闸门
