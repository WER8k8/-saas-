## 2. 关键认知（质量部门核验点 · 防"双 executor 可真跑"被误读）

**"可真跑" ≠ "已真跑"。** 两侧的物理就绪落点不同，必须分开标注：

### 2.1 TradeAI Agent（子系统⑤）—— vendor 嫁接，可真跑
- 走 `adapters.tradeai`（命名空间隔离 `tradeai_vendor`，`_resolve_tradeai_backend()` 指向 `_external/trade-ai-agent/backend`）。
- `is_available=True`：能 import + 三核心类（BaseSkill/WorkflowEngine/AgentOrchestrator）齐全 → **可真跑**。
- 诚实边界：真跑时若外部社媒/WhatsApp 无凭据，`orch.execute_workflow()` 应失败并列出可用能力，**不编造**（v3 F18）。
- 合规提醒：vendor 根目录无 LICENSE（MIT 根目录），商用需书面确认。

### 2.2 GoodJob CRM（子系统⑥）—— HTTP 桥，配置即真跑 / 未配置诚实失败
- **不走 vendor 目录**（`goodjob-crm/backend` 的 `app/core` 为空），走 `services/goodjob/trade_document_bridge` 真实 HTTP 桥
  （`orchestration/executors/goodjob_executor.py` 的 `GoodJobExecutor`，链路 `UJ --HTTP--> GoodJob /api/uj-bridge/task-packages`）。
- `enabled = bool(GOODJOB_BASE_URL)`：
  - 配置 `GOODJOB_BASE_URL` → **可真跑**（submit 派发五字段任务包，幂等去重）；
  - 未配置 → `build_goodjob_executor()` 返回 None → 外层明确 `failed: goodjob_bridge_disabled`，**绝不造假单证/假银行账号/假 SWIFT**（此前危险 mock 已移除）。
- 桥自带校验：缺 `tenant_id`/`inquiry_id`、`doc_type` 非白名单、条目 >200 均 `ValueError` 如实透出，不绕过。
